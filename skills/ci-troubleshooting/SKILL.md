# Диагностика CI

## Процесс

1. Зафиксировать workflow, job, step, commit и первую содержательную ошибку.
2. Отделить первичный сбой от каскадных сообщений.
3. Сравнить локальную и CI-среду: OS, Python, lock, permissions, cwd, secrets и cache.
4. Воспроизвести минимальную команду локально, если возможно.
5. Сформулировать одну гипотезу и проверить одним изменением.
6. Проверить детерминированность: version pin, cache key, сеть, время, порядок, concurrency.
7. Исправить причину минимально; не отключать scanner/test/typecheck.
8. Запустить целевой job, затем локальный эквивалент и проверить новый GitHub run.

## Нельзя сокращать

- Не перезапускать workflow многократно без новой гипотезы.
- Не использовать `continue-on-error` для обязательной проверки.
- Не расширять permissions ради неопределённой ошибки.
- Не считать локальный green доказательством CI green.

## Red flags

- Исправляется последняя ошибка вместо первой.
- Используется mutable action tag для чувствительного шага.
- Cache скрывает изменение lock/config.
- Секрет пытаются вывести в лог.

## Результат

Вернуть первопричину, доказательства, исправление, реально выполненные проверки и остаток,
который можно подтвердить только в GitHub.

## Проверка

- Новый run завершён ожидаемо.
- Gate не ослаблен.
- Локальная и CI-команды документированно соответствуют друг другу.

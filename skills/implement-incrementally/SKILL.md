# Пошаговая реализация

## Процесс

1. Проверить план и выбрать первый незаблокированный шаг.
2. Зафиксировать исходное состояние и релевантную команду проверки.
3. Для изменения поведения применить `$tdd`.
4. Реализовать только один вертикальный срез: вход → логика → наблюдаемый результат.
5. Выполнить проверку шага и изучить diff.
6. Обновить статус плана и документацию.
7. Продолжить только при зелёном состоянии; при неожиданном сбое перейти к
   `$debug-systematically`.
8. После всех шагов выполнить Definition of Done из
   `../../references/definition-of-done.md`.

## Нельзя сокращать

- Не открывать несколько зависимых шагов одновременно.
- Не накапливать непроверенный код до конца плана.
- Не смешивать рефакторинг вне scope с функциональным изменением.
- Не продолжать после красной обязательной проверки.

## Red flags

- Diff невозможно описать одним результатом.
- Проверка шага появится «позже».
- Возник новый архитектурный выбор, но план не пересмотрен.
- Половина работы состоит из будущих hooks и пустых abstractions.

## Результат

Для каждого среза зафиксировать результат, изменённые границы и доказательство. В конце вернуть
сводку по критериям приёмки и остаточным рискам.

## Проверка

- Каждый шаг завершён отдельно и оставляет согласованное состояние.
- Diff не содержит несвязанных изменений.
- Все обязательные проверки действительно запускались.

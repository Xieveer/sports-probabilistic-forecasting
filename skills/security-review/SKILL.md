# Ревью безопасности

## Процесс

1. Определить активы, субъектов, недоверенные входы и границы доверия.
2. Проследить данные до хранилища, сети, shell, шаблона, ML-модели и логов.
3. Проверить authentication, authorization и изоляцию пользователей/задач.
4. Проверить секреты, персональные данные, диагностические сообщения и retention.
5. Проверить validation, timeout, лимиты, размер входа, path traversal и безопасные defaults.
6. Оценить новую зависимость, install scripts, provenance и закрепление версии.
7. Проверить CI permissions, fork PR, Docker user и передачу secrets.
8. Выполнить доступные автоматические проверки и отделить их результат от ручного анализа.

Применить `../../references/security-checklist.md` только к затронутым границам.

## Нельзя сокращать

- Не называть style smell уязвимостью без достижимого сценария.
- Не выводить найденный секрет целиком.
- Не считать scanner заменой threat model.
- Не исправлять риск ослаблением security gate.

## Red flags

- Доверие определяется данными от клиента.
- В лог попадает token, сообщение пользователя или полный API response.
- Сетевой вызов не имеет timeout/лимита.
- Action или image использует плавающий непроверенный tag.

## Результат

Для каждой находки указать актив, сценарий атаки, предусловия, влияние, вероятность, меру и
остаточный риск. Разделить vulnerability, hardening и непроверенную гипотезу.

## Проверка

- Все изменённые границы доверия рассмотрены.
- Findings воспроизводимы или явно требуют дополнительной проверки.
- Секреты и персональные данные не раскрыты в отчёте.

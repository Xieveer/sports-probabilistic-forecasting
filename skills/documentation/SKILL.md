# Документирование

## Процесс

1. Определить аудиторию и действие, которое она должна выполнить.
2. Выбрать каноническое место:
   - README — старт и частые операции;
   - `docs/` — подробный процесс;
   - ADR — причина значимого решения;
   - docstring — контракт Python API.
3. Писать пользовательский текст на русском, идентификаторы — на английском.
4. Для публичного Python API использовать Google style: `Args`, `Returns`, `Raises`.
5. Проверить команды, пути, variables и примеры по коду.
6. Удалить устаревшее описание вместо добавления противоречащего.
7. Собрать документацию строгой командой и проверить ссылки.

## Нельзя сокращать

- Не описывать возможность, которой ещё нет.
- Не копировать один текст в README, docs и comments.
- Не пересказывать сигнатуру вместо объяснения контракта.
- Не оставлять placeholder без явной задачи.

## Red flags

- Пример невозможно запустить.
- Название переменной отличается от `.env.example`.
- Документ сообщает результат проверки, которая не запускалась.
- ADR описывает только выбранный вариант.

## Результат

Вернуть обновлённый канонический документ и список проверенных примеров/команд.

## Проверка

- Поведение и эксплуатация соответствуют коду.
- `make docs` проходит.
- Нет дублирующих или противоречивых инструкций.

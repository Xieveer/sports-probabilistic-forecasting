# ADR-030 — Локальный цикл кандидата из каталога портфеля

> **Статус:** accepted
> **Дата:** 2026-10-10
> **Требование:** [REQ-029](../../product/requirements/REQ-029-premier-league-candidate.md)
> **Развивает:** [ADR-003](ADR-003-configured-multisport-portfolio.md)

## Контекст и критерии выбора

Для первого нового футбольного турнира уже есть совместимый локальный CSV, но
`dvc.yaml` и Airflow содержат статические списки. Каталог портфеля уже валидирует
связь tournament → source → model pool → market/spec, однако не запускает путь
до отчёта кандидата. Нужен один проверяемый цикл без включения расписания и
production pointer. Источник исторических odds пригоден только для исследования.

## Рассмотренные варианты

1. **Добавить `premier_league` в DVC и Airflow списки.** Мало нового кода, но
   следующий турнир снова требует ручного изменения нескольких списков.
   Candidate может случайно попасть в регулярный refresh.
2. **Локальная команда по candidate-профилю каталога (выбрано).** Она вызывает
   существующие ingest, clean, features и train, проверяет выход каждого шага и
   строит отчёт из завершённого MLflow run. Нового процесса или scheduler нет.
3. **Новый сервис управления кандидатами.** Дал бы отдельный API и очередь, но
   для одного владельца добавляет состояние и эксплуатацию без проверенной
   потребности.

## Решение

Candidate-профиль задаёт алгоритм, набор признаков и профиль odds. Локальная
команда принимает имя профиля и использует только файловый source, уже имеющий
`source.csv`. Она завершает работу ошибкой при пропущенном файле, необновлённом
этапе, несовпадении соревнования, неполных метриках или отсутствующем trace.
Отчёт содержит хэш обработанного датасета, MLflow run ID, фактическое тестовое
окно и идентификатор набора матчей, ML/betting-метрики и bootstrap-разброс ROI.
Trainer использует trailing test fraction; фиксированный календарный holdout
этот срез не обещает. Состояние остаётся `candidate`; команда не меняет
deployment profile, pointer, расписание и бот.

## Последствия

- Следующий турнир с тем же файловым контрактом подключается данными и YAML.
- DVC и Airflow сохраняют свои прежние production-сценарии; их списки пока не
  заменены каталогом. Для регулярной выдачи потребуется отдельный срез.
- Локальный MLflow DB и исходный CSV нужны для полного повторения результата.
  JSON-отчёт хранит краткое evidence, но не заменяет эти входы.
- Исследовательские odds Smart Tables не подтверждены как prematch; финансовый
  результат нельзя считать основанием для promotion.

## Проверка и пересмотр

Проверить полный запуск на локальном `ENG1`, отказ для неверных/пустых данных и
регрессию NHL. Пересмотреть решение, если появится согласованный источник будущих
матчей и владелец запросит регулярную выдачу либо если несколько одновременных
candidate-run потребуют независимого расписания.

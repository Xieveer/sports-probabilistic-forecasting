# ADR-009 — Исполнимый контракт gates процесса агентов

> **Статус:** accepted
> **Дата:** 2026-08-16
> **Связанное требование:** [REQ-009](../../product/requirements/REQ-009-agent-workflow-gates.md)

## Контекст и критерии выбора

Правила уже назначали reviewer commit/push, но его профиль был `read-only`, а валидатор
проверял только форму AI-слоя. Нужны минимальные правила, которые не позволят вернуть это
противоречие и сохранят evidence процесса в документации.

## Рассмотренные варианты

1. **Status quo:** текстовые правила без проверки; не предотвращает несовместимый профиль.
2. **Вариант A:** расширить `make ai-validate` семантическими проверками и дать reviewer
   `workspace-write` для его commit/documentation gate.
3. **Вариант B:** выполнить commit отдельной release-ролью; добавляет роль и handoff без
   требования пользователя.

## Решение

Принят вариант A. Reviewer сохраняет запрет на изменение production-кода автора, но получает
write-доступ, необходимый для commit/push и записи evidence review. `ai-validate` проверяет
этот профиль и обязательные формулировки в канонических документах и templates.

## Последствия

- Положительные: назначенная ответственность технически выполнима и проверяется локально.
- Отрицательные и стоимость: text-based gate требует обновлять проверяемые документы вместе с
  процессом.
- Безопасность и эксплуатация: push по-прежнему требует Git-авторизации и не выполняется без
  явной задачи; reviewer не получает права менять scope или production-код автора.

## Проверка и пересмотр

`make ai-validate` и целевые unit-тесты подтверждают контракт. Решение пересматривается, если
Codex даст reviewer отдельное минимальное permission для Git без общего `workspace-write`.

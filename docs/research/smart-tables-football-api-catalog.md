# Smart Tables football API — проверяемый каталог

Машиночитаемый источник истины: [smart-tables-football-api.json](catalogs/smart-tables-football-api.json). Это снимок неофициального backend `https://backend.smart-tables.ru/api/v1`, а не обещание стабильного публичного API.

## Статус и границы

`last_verified`: 2026-08-25. Поля и методы сверены с локальной безопасной разведкой от 2026-05-31 и fixtures матча; повторный GET из текущей среды не выполнился, так как DNS не разрешил host. Это не интерпретируется как ответ источника. Карточка не хранит payload, cookie, HAR, credentials либо путь обхода CAPTCHA/ACL.

Каждый `evidence` в JSON-card — объект `{reference, as_of, evidence_level}`. `reference` указывает безопасный локальный артефакт либо read-only path/type observation; `as_of` — дата именно этого наблюдения, не дата создания каталога; `evidence_level` отличает fixture, сохранённую локальную разведку и повторный безопасный GET. У каждого `api_field` также есть `units` и `domain`: если единицы или полный домен API не доказаны, это прямо указано, а не выводится по названию поля.

Открытый public GET не означает разрешения на массовую выгрузку или production-использование: официального versioned contract и подтверждённой лицензии нет. HTML-фронт не является частью этого контракта; в локальном наблюдении он защищён CAPTCHA. `acl-page-render` вернул 403 для части UI и остаётся недоступным.

## Как читать temporal-метки

`pre_event` — структурно известно до начала; `pre_event_if_timestamp_checked` — только если сохранён снимок, сделанный до `begin_at`; `live` — может появиться во время матча; `post_event` — нельзя использовать в предматчевой feature. Значение из законченной карточки не доказывает, что оно было доступно до kickoff.

## Граница complete-каталога

Field-level scope: `match-card`, `match-list`, `match-stat`, `match-chart`, `match-center-stat-odds` (только `totals`) и `competition-by-slug`. Остальные публично наблюдаемые routes перечислены в `catalog_scope.unobserved_endpoint_ids`: для них нет выдуманных полей. `acl-page-render` фактически denied; probe `nearest-matches` не засчитан из-за URL-encoding fault. `match-center-card` уже ответил 200, но остаётся `unobserved`, пока не создан полный leaf dictionary по paths-only capture.

## Словарь полей: список матчей

`match-list` в read-only GET от 2026-08-25 вернул `success`, `data.total` и `data.items[]`. Полный JSON path/type record хранится в JSON-card. У item подтверждены: ID матча/match-center/турнира/сезона/команд/судьи, `begin_at`, `status`, итоговые голы, 1X2 odds, market value, а также вложенные `home_team`/`away_team` (`id`, `title`, `common_title`, `1xbet_name`, `is_national`, `total_market_value`, `slug`, `logo`, `image`).

Temporal policy совпадает с карточкой: scores — `post_event`; status — `live`; odds и market value — только `pre_event_if_timestamp_checked`; IDs и scheduled context — metadata. В header наблюдался `X-RateLimit-Limit: 10000`; это единичное наблюдение, а не опубликованный лимит или разрешение на массовую выгрузку.

## Охват, пропуски и безопасное применение

Локальный каталог от 2026-05-31 содержал 37 турниров сборных и около 11 599 матчей; два турнира имели нулевой счётчик, а четыре slug со страницы UI дали 404. Это историческое наблюдение, а не текущий SLA. Reviewer повторно получил read-only `/matches` и наблюдал `X-RateLimit-Limit: 10000` (2026-08-25); это не является опубликованным лимитом и не разрешает bulk collection. Для historical backtest не использовать текущие standings, H2H, team/referee aggregates, predictions или odds без отдельного versioned as-of dataset: API не доказал, что они восстанавливают состояние на дату матча.

Для engineering обязательны: раздельные ключи `match_id`/`match_center_id`, pagination `/matches`, null-safe statistics, cache provenance и timestamp odds. Для player/lineup hypothesis Smart Tables не является достаточным источником.

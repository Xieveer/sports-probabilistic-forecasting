# Project Rules — Sports Probabilistic Forecasting

Вы работаете внутри MLOps-проекта промышленного уровня для вероятностного прогнозирования спортивных событий.
Основная цель проекта: сервис прогнозирования вероятностей предстоящих матчей, калибровка этих верояностей прямо влияет на итоговую доходность от value-ставок в беттинге


## Общие принципы
Проект — это конфиг-управляемый ML-движок: поведение определяется Hydra-конфигами, код — стабильная платформа.

Не плодить конфиги ради комбинаций. Новые конфиги добавляются только когда:
1) появляется новый source формат,
2) появляется новый подтурнир,
3) появляется горизонтальное расширение (новые генераторы фич, модели, протоколы обучения).
Комбинации собираются через Hydra overrides.

Entry points должны быть тонкими. CLI и main.py не содержат бизнес-логики.

Разделение ответственности:
- source → vendor/source → raw parquet
- tournament → view/валидации
- market → форма датасета
- market_spec → таргет и параметры
- features → генерация признаков
- model → алгоритмы
- train → протокол обучения
- deploy → прод-выбор модели

## Докстринги и стиль
Использовать Google-style docstrings.
Type hints обязательны.
Использовать pathlib.
Обновлять документацию sphinx

## Конфиги Hydra
Использовать композицию через defaults.
Запрещено создавать recipe-конфиги.
Не использовать eval() для таргетов — только builder + params.

## DVC
Все стадии описываются в dvc.yaml.
Все пути берутся из conf/paths.yaml.
Seed фиксируется, конфиги сохраняются.

## Airflow
Все пайплайны запускаются через CLI.
Никакой airflow-логики внутри ML-кода.

## Features и leakage
Фичи могут использовать только данные до начала матча.
Запрещено использовать данные текущего матча если они из будущего.
Пример: форма игрока известна для текущего матча, счет матча информация из будущего

## Модели
Все модели реализуют BaseModel интерфейс.
Ансамбли собираются через ModelFactory.

## Метрики и MLflow
Все train и business метрики логируются в MLflow.
Сохраняются артефакты и snapshot конфигов.

## Commands.py
По умолчанию не нужен.
Разрешён только как генератор sweep-команд без бизнес-логики.

## Definition of Done
- соблюдены слои ответственности
- DVC воспроизводим
- все метрики пишутся в MLflow
- leakage guard соблюдён
- добавлены тесты

## Makefile
- пользуйся готовыми командами
- все изменения кода нужно проверять: make pre-commit и make test

## Интсрукции
- писать инструкции о проделанной работе только в docs/instructor
- держать их в актуальном виде и при необзодимости изучать, чтобы не перебирать весь код каждый раз заново

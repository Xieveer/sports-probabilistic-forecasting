**Назначение этого документа:** точка входа для описания *что* делает продукт, *для кого* и *какие сущности* составляют домен. Здесь — ценность, возможности и сквозные сценарии без перечисления инструментария и правил работы в репозитории.

**Технический контекст (стек, `make`, индекс файлов, правила для ИИ):** [.cursor/rules/00-core.mdc](../../../.cursor/rules/00-core.mdc) (от корня репозитория: `.cursor/rules/00-core.mdc`).

## Продукт и ценность

Промышленная MLOps-платформа для **вероятностного прогнозирования спортивных событий**. Итог для бизнеса — **сервис калиброванных вероятностей** по предстоящим матчам: качество калибровки напрямую влияет на применимость прогнозов в стратегиях **value-ставок** (ожидаемая доходность при согласовании модельных вероятностей с линией букмекеров).

Поведение системы в целом **задаётся конфигурацией** (турниры, рынки, спецификации, протоколы обучения): код — стабильная платформа, сценарии — в конфигах и пайплайнах.

---

## Основные бизнес-возможности

| Область | Что даёт продукт |
|--------|-------------------|
| Данные | Приём и нормализация данных из разных источников, разрез по турнирам/подтурнирам, подготовка датасетов под рынки (winner, тоталы и т.д.). |
| Моделирование | Обучение и сравнение моделей, калибровка вероятностей, отбор признаков, симуляция беттинга для оценки ROI/риска. |
| Эксплуатация | Продакшен-выбор модели, batch-материализация прогнозов в БД, read-only API для выдачи вероятностей. |
| Наблюдаемость | Трекинг экспериментов и метрик, мониторинг дрифта и качества на оркестрации. |

Entry points (CLI, `main`) остаются **тонкими**: бизнес-логика сосредоточена в слоях данных, фич, обучения и сервиса — см. структуру в [repo-index.md](repo-index.md).

## Доменные сущности и ответственность

Смысловое разбиение (что за что отвечает в продукте):

- **source** — поставщик/формат сырых данных → **raw** в едином виде.
- **tournament** — турнирный контекст, представления и проверки данных.
- **market** — семейство рынков и форма датасета под тип исхода.
- **market_spec** — конкретный таргет и параметры (например, база тотала).
- **features** — признаки до начала матча (без утечки из будущего).
- **model / train** — алгоритм и протокол обучения.
- **deploy** — какая модель считается продакшен и как продвигается.

Комбинации сценариев по возможности собираются **переопределениями конфигов**, а не размножением файлов «на каждую комбинацию»: новые конфиги оправданы новым источником, подтурниром или **горизонтальным** расширением (новые генераторы фич, модели, протоколы).

## Сквозной сценарий: от данных до потребителя

1. **Поступление и качество** — ingest → clean → валидации; пути и воспроизводимость пайплайна данных (в т.ч. DVC) обеспечивают повторяемость результатов для аудита и релизов.
2. **Обучение и оценка** — кросс-валидация по времени, калибровка, бизнес-метрики (в т.ч. через симуляцию ставок), сравнение с базовыми линиями.
3. **Продакшен** — выбор модели, материализация прогнозов в хранилище.
4. **Потребление** — API и/или downstream-процессы, использующие вероятности для решений.

Оркестрация сценариев (например, Airflow) **вызывает** те же CLI/ступени, что и разработка; в ML-коде не дублируется «логика оркестратора» — см. [service_orchestration_architecture.md](service_orchestration_architecture.md).

## Ограничения домена (риски для ценности)

- **Утечка из будущего:** признаки и таргеты строятся только из информации, доступной **до начала матча**; использование «будущего» по отношению к моменту прогноза недопустимо (иначе завышенное качество и несостоятельность в проде).
- **Калибровка и линия:** прогноз имеет смысл для value-стратегий, когда вероятности сопоставимы с рыночными коэффициентами и учитываются издержки/ограничения реального беттинга.

---

## Критерии готовности изменений (бизнес-уровень)

- Сохраняется разделение слоёв (данные → фичи → обучение → выкладка).
- Результат воспроизводим по зафиксированным конфигам и пайплайну данных.
- Метрики обучения и продуктовые метрики трассируются (например, в MLflow).
- Учтены ограничения по утечке; добавлены тесты там, где меняется поведение.

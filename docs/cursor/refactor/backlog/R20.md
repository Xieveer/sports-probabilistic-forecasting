# R20. Pinnacle odds — историческая загрузка 3 сезонов + инкрементальный автоапдейт

> **Статус:** 🟡 В работе
> **Приоритет:** 🔴 High
> **Сложность:** High

---

## Проблема

В R19 (done) реализованы `OddsApiClient`, `backfill.py` (CLI), `enrichment.py` (merge odds → source.csv). Однако:

1. **Нет персистентного хранения odds в source-слое** — backfill выдаёт разовый DataFrame / опциональный parquet, но стандартного «файла коэффициентов» между запусками нет.
2. **Нет автоматического вызова** — odds backfill/refresh только через CLI вручную; не интегрирован в `source_refresh.py` и Airflow DAG `data_refresh`.
3. **Нет надёжного resume/checkpoint для odds** — при прерывании run нет явного маркера прогресса по датам и гарантий продолжения «с места остановки» без потери уже загруженного.
4. **Нет инкрементальной логики** — backfill проходит весь указанный диапазон; нет определения «что нового с прошлого запуска».
5. **Нет конфигурации сезонов** — для multi-season backfill нужно знать границы (NHL: Oct–Jun).
6. **Нет registry нормализации команд** — ручной alias-маппинг не выделен в отдельный управляемый слой.
7. **Нет валидации** — отсутствуют Pandera-проверки для odds-колонок, метрики coverage.
8. **Нет тестов интегрированного flow** — отдельные unit-тесты (client, enrichment) не покрывают пайплайн целиком.

**Цель:** собрать историю Pinnacle за 3 сезона (2023-24, 2024-25, 2025-26), хранить в source-слое как parquet, настроить автоматическое обновление odds вместе с NHL source refresh каждые 4 часа.

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Исчерпание квоты The Odds API при историческом backfill (~1800+ дней × 2 snapshot = 3600 запросов) | 🔴 Высокая | Кэш на диск (уже есть), `single-snapshot` для экономии, бюджет квоты в конфиге, прогон по частям |
| Потеря прогресса при прерывании загрузки | 🟡 Средняя | Явный checkpoint-файл/метаданные прогресса odds + idempotent upsert в store + атомарная запись |
| Низкий match rate при merge (разные нормализации команд NHL / Odds API) | 🟡 Средняя | Ввести TeamNameRegistry (alias → canonical), логировать unmatched и пополнять registry |
| Historical endpoint The Odds API не покрывает все дни / есть пропуски | 🟡 Средняя | Graceful skip дней без данных (уже есть), coverage-метрика в логе |
| Конфликт при одновременном обновлении source.csv (NHL fetch + odds merge) | 🟢 Низкая | Выполнять odds refresh как post-step внутри того же lock-контура |

## Критерии готовности (DoD)

1. `OddsStore` читает/пишет parquet, upsert не создаёт дублей
2. CLI `backfill.py --seasons 3 --tournament nhl --store` загружает 3 сезона и сохраняет в store
3. `source_refresh --tournament nhl` автоматически делает инкрементальный odds refresh + merge
4. Airflow DAG `data_refresh` при запуске с `nhl` обновляет и NHL-данные, и odds
5. Pandera-валидация odds-колонок проходит без ошибок
6. Coverage >= 70% для завершённых матчей с odds
7. Все новые модули покрыты тестами (≥ 80% строк)
8. Квота API не превышается при автоматическом refresh (бюджет ≤ 100 запросов/run)
9. После принудительного прерывания refresh следующий запуск продолжает обработку с checkpoint без потери уже записанных odds
10. TeamNameRegistry применён в merge-пайплайне; unmatched пары логируются и доля match-rate документирована

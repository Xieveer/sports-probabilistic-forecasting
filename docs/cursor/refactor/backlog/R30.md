# R30. Инвариант таргета winner_withOT vs счёт (long) и защита trace

> **Статус:** 🟡 В работе
> **Приоритет:** 🔴 High
> **Сложность:** Medium

---

## Проблема

На `test_bet_trace.csv` пользователь добавил колонку `y` как «победа `pl` по голам с ОТ» (`pl_goals_full > opp_goals_full`) и увидел расхождение с `y_true` из пайплайна. Это **критично**: при реальной инверсии таргета все метрики и беттинг-симуляция бессмысленны.

**Проверка в репозитории (2026-05-09):** на полном `train_long.parquet` таргет из `compute_target_from_market_spec` совпадает с `(pl_goals_full > opp_goals_full)` — **0 несовпадений**. При этом **на holdout после сортировки как в старом `trainer.py`** расхождение **872 строки** — из‑за бага: после `sort_values(...).reset_index(drop=True)` выражение `target.iloc[df.index]` при `RangeIndex(0..n-1)` **не** переупорядочивало таргет по строкам отсортированного `df` (брался прежний порядок по позициям). **Исправлено** в `trainer.py` (`target.loc[sort_order]`). Файл `test_bet_trace.csv` пользователя сгенерирован **до** фикса и содержит неверный `y_true` относительно голов в строке.

Остаётся полезным: явная колонка в trace, assert, документация Excel (R30.1–R30.4).

---

## Почему это «проскочило» мимо тестов

1. **Unit-тесты таргета** (`tests/test_nhl_ot_market_targets.py`) строят **синтетический** wide→long — порядок строк не меняется так, как после `sort_values` на реальном parquet.
2. **Нет инварианта** «`y_true` == `(pl_goals_full > opp_goals_full)`» на holdout после сортировки в тренере (до фикса).
3. **Интеграционные тесты тренера** не сверяли таргет с голами на test slice.
4. Баг **сортировка vs `iloc`** не покрывался отдельным тестом (добавлен `tests/test_trainer_target_sort_alignment.py`).

## Проблема

R22 даёт baseline NHL (winner/total на основное время + OT-рынки). Следующий горизонт продукта — **расширение линейки маркетов** за пределы исхода и тотала:

1. **Team-level stat markets** — пари на командную статистику матча: броски в створ (SOG), 2-минутные удаления, голы в большинстве, вбрасывания, хиты (и возможность легко расширить список).
2. **Player-level prop models** — индивидуальные ставки: очки, голы, передачи, штрафные минуты, хиты, SOG, +/−, очки в PP (полный состав или выборка «звёздных» игроков).
3. **Lineup-driven inference** — если модели зависят от составов:
   - подгрузка *ожидаемого состава* из стороннего сервиса;
   - обновление *точного состава* из официального протокола за ~60 мин до матча;
   - пересчёт (rematerialize) прогнозов при существенном изменении состава.

Эпик **не заменяет** R22 (baseline + OT) — он расширяет продуктовую вертикаль после завершения R22.1–R22.3 и, желательно, R22.8.

## Фазы

### Фаза A — Командная статистика из boxscore (R25.1–R25.5)

Цель: новые market family/spec для team-level stats (SOG, 2-min penalties, PP goals, faceoffs, hits), target sources и первый training sweep. Данные уже присутствуют в `source.csv` / `ice_hockey.yaml` (`home_sog_ft`, `home_hits_ft`, `home_pim_ft`, `home_2pim_ft`, `home_fow_ft`); PP goals может потребовать расширения ассемблера.

### Фаза B — Player-level props: данные, схема, модели (R25.6–R25.10)

Цель: player-entity grain (одна строка = один игрок × матч), таргеты (points, goals, assists, PIM, hits, SOG, ±, PP points), feature generator для player rolling stats и baseline sweep.

### Фаза C — Lineup provider + protocol refresh (R25.11–R25.14)

Цель: абстракция внешнего lineup-провайдера, интеграция ожидаемых составов, обновление из официального протокола за ~60 мин, хранение diff.

### Фаза D — Rematerialize при изменении состава (R25.15–R25.17)

Цель: политика «когда пересчитывать» (threshold, какие heads), дельта-materialize pipeline, инвалидация API-кеша.

### Фаза E — Telegram hooks (R25.18)

Цель: уведомление подписчиков «lineup locked / refreshed picks». Реализация внутри R24 scope, здесь — только контракт и триггер.

## Риски и митигации

| Риск | Митигация |
|------|-----------|
| PP goals отсутствует в текущем boxscore extract | R25.1 — проверить `powerPlayGoals` в NHL API; fallback — derived из PBP |
| Player prop grain × N players → очень большой dataset | Ограничить scope: top-N minGP или «star» subset; feature generator — vectorized |
| 3rd-party lineup API нестабилен / платный | ABC позволит подменить провайдера; кеш + graceful degradation |
| Rematerialize race condition (запрос во время пересчёта) | Upsert + version field; кратковременная stale response допустима |
| Scope creep — слишком много маркетов сразу | Фазы A и B можно выполнять параллельно, но каждый sweep — ≤2 маркета за итерацию |

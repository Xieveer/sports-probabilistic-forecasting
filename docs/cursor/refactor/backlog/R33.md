# R33. Согласованность `market` и `market_spec` (устранение двусмысленности)

> **Статус:** 🟡 В работе
> **Приоритет:** 🟡 Medium
> **Сложность:** Low

---

## Проблема

Hydra собирает конфиг из двух независимых групп defaults: `market` (`cfg.market.family`) и `market_spec` (`cfg.market_spec`). Их можно несогласованно переопределить в CLI, например `market=winner market_spec=winner_withOT`. В этом случае:

- **Таргет, odds, пути к артефактам** берутся из `market_spec` (фактически обучаем `winner_withOT`).
- **Имя MLflow-эксперимента и тег `market_family`** строятся из `cfg.market.family` (в UI попадает в `…__winner__…`), что вводит в заблуждение при сравнении запусков и аудите.

Валидация в `validate_experiment_config` сейчас не проверяет согласованность семейств. Поле `market_family` уже есть во всех актуальных `conf/market_spec/*.yaml`.

Связанный эпик: **R16.2** (стандартизация именования экспериментов в MLflow) — после R33 имена экспериментов снова станут предсказуемыми при корректном CLI.

---

## Что сделать

- [ ] **R33.1** В `validate_experiment_config` (`sports_forecast/config/validation.py`): если у `cfg.market_spec` задано `market_family`, проверять `cfg.market.family == cfg.market_spec.market_family`; при расхождении — `ConfigValidationError` с текстом, включающим подсказку вида «используйте `market=winner_withOT market_spec=winner_withOT`».
- [ ] **R33.2** Юнит-тесты: успешная пара; ошибка при `winner` + спек `winner_withOT`; при необходимости — фикстуры минимального `DictConfig` без полного Hydra.
- [ ] **R33.3** Короткий раздел в пользовательской документации (предпочтительно `docs/source/` ops/quickstart или существующий гайд по обучению): явное правило «`market` и `market_spec` должны относиться к одному семейству рынка», пример корректной команды для NHL `winner_withOT`, отсылка к имени эксперимента в MLflow.
- [ ] **R33.4** (Опционально) В `train.py` после валидации: один INFO-лог «resolved market families: market.family=…, market_spec.market_family=…, mlflow experiment=…» для трассировки без чтения UI.

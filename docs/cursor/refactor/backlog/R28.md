# R28. Унификация rolling-контекстов через семантические алиасы колонок

> **Статус:** 🟡 В работе
> **Приоритет:** 🟡 Medium
> **Сложность:** Medium

---

## Проблема

Контексты в `context_library.yaml` содержат хардкод имён реальных колонок:
- `tour_num` → `keys: ["pl", "tour_num"]` (реальная колонка `tour_num` в данных)
- `match_num` → `keys: ["pl", "tour_match_num"]`
- `weekday` → `keys: ["pl", "weekday"]`

Это работает только если во всех спортах одинаковые имена колонок. Но семантика разная:

| Абстрактный контекст | Table Tennis / Cyberhockey | NHL |
|---|---|---|
| `tour_num` | внутри-дневной мини-турнир (3–8 матчей) | нет прямого аналога |
| `match_num` | номер матча в мини-турнире | номер игры в сезоне |
| `inseason` | не существует | группировка по `season` (82 игры) |

Для NHL нужен контекст `inseason` (сброс EWM при смене сезона), что требует
группировки по колонке `season`, которой нет в TT/cyberhockey. Кроме того,
если один и тот же абстрактный контекст должен маппиться на разные колонки
в разных спортах, текущая архитектура этого не поддерживает.

### Целевое состояние

Разделить **семантику контекста** (что означает, определяется в `context_library.yaml`)
и **конкретные колонки** (какая колонка реализует это понятие, определяется в `conf/sport/*.yaml`).

## Дизайн-решения

### 1. Плоский column-level alias (рекомендован)

Альтернативы рассмотрены и отвергнуты:

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| **A) Placeholder-шаблоны** `{season_col}` в library keys | Явная связь | Ломает обратную совместимость, OmegaConf/Hydra сложности |
| **B) Context-level overrides** в sport config | Гибко | Дублирует структуру definitions, verbose |
| **C) Column-level alias** в sport config ✅ | Минимальный diff, один уровень индирекции, обратная совместимость | Потенциальная неоднозначность если одна колонка в разных семантиках |

Выбран **подход C**: sport-конфиг задаёт `rolling_column_aliases: { old_col: new_col }`.
При сборке контекстов `rolling_contexts.py` заменяет имена колонок в `keys`.

```python
def _resolve_keys(keys: list[str], aliases: dict[str, str]) -> list[str]:
    """Заменить имена колонок через aliases. Неизвестные ключи остаются как есть."""
    return [aliases.get(k, k) for k in keys]
```

### 2. Scope изменений

| Компонент | Изменяется? | Почему |
|-----------|------------|--------|
| `rolling_contexts.py` | ✅ Да | Загрузка aliases, resolution, валидация |
| `context_library.yaml` | ✅ Да | Новые контексты (`inseason`, `h2h_inseason`) |
| `conf/sport/ice_hockey.yaml` | ✅ Да | `rolling_column_aliases`, `inseason` в names |
| `conf/sport/table_tennis.yaml` | ⚪ Нет | Без aliases — поведение не меняется |
| `conf/sport/cyberhockey.yaml` | ⚪ Нет | Без aliases — поведение не меняется |
| `EWMFeatureGenerator` | ⚪ Нет | Получает уже разрешённые keys |
| `CountFeatureGenerator` | ⚪ Нет | Получает уже разрешённые keys |
| `pipeline.py` | ⚪ Нет | Не участвует в resolution |

### 3. Именование фичей

Имя фичи строится по **абстрактному имени контекста** (ключ в `definitions`),
не по реальной колонке:
- `inseason` → `f_pl_inseason_diff_ewm_5`
- `tour_num` → `f_pl_tour_num_diff_ewm_5`

Это уже работает в текущем коде — `ctx["name"]` используется в naming helpers.

### 4. Валидация

- На этапе конфига (`expand_rolling_generators_inplace`): логируем resolved keys
- Наличие колонки в DataFrame проверяется в генераторе (existing `missing columns` warning)
- Если контекст запрошен в `rolling_context_names`, но alias для его колонки не задан —
  колонка используется as-is (обратная совместимость)

### 5. Связь с R27

R27.7 планирует наивно добавить `inseason` с хардкодом `["pl", "season"]`.
R28.2 перекрывает R27.7: добавляет `inseason` в library как часть этого эпика.
После R28 задача R27.7 считается выполненной; R27.8 (верификация) остаётся актуальной.

### R28.4 — Backward compat: TT + cyberhockey без изменений

  `uv run pytest tests/ -k "rolling or ewm or count"` (если есть)

- **Файлы:** проверка; при необходимости `conf/sport/table_tennis.yaml`,

  в library — уже есть проверка (ValueError); убедиться что она работает и для
  новых контекстов

## Риски и митигации

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| Alias перезаписывает колонку, нужную другому контексту | Low | Column-level alias действует глобально; если конфликт — использовать context-level override (добавить позже) |
| `season` отсутствует в long format NHL | Low | Проверить `wide_to_long` — `season` как meta-колонка проходит; если нет — добавить в `select_columns` |
| Hydra DictConfig не поддерживает `rolling_column_aliases` как plain dict | Low | `OmegaConf.to_container(resolve=True)` конвертит в dict; тестируем в R28.6 |
| Изменение `rolling_context_names` для NHL ломает существующие обученные модели | Medium | Фичи переименовываются (исчезают `tour_num`, появляется `inseason`) — нужна перетренировка; это ожидаемо в рамках R27 Feature Engineering v2 |

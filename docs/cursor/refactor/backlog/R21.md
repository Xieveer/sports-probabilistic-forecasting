# R21. Multi-bookmaker odds: Pinnacle (OT) + 1xBet (regulation), total line, dynamic snapshots

> **Статус:** 🟡 В работе
> **Приоритет:** 🔴 High
> **Сложность:** High

## Проблема

R19/R20 реализовали odds-пайплайн для **одного** букмекера (Pinnacle) с **фиксированными** UTC-timestamps снимков (12:00, 23:30) и **без** хранения базы тотала (point/line). Новые требования:

1. **Pinnacle** — рынки "winner incl OT" (2-way moneyline) + "totals incl OT". Хранить **базу тотала** (`point`, например 5.5) помимо цен over/under.
2. **1xBet** (ключ `onexbet` в The Odds API) — рынки "winner in regulation" (1X2, с ничьей) + "totals in regulation". Хранить базу тотала.
3. **Контракт именования маркетов (обязательный):**
   - `winner` / `total` — только для **основного времени** (regulation);
   - `winner_withOT` / `total_withOT` — для **полного матча** (с учетом ОТ и буллитов).
3. **Динамические снимки** — вместо hardcoded UTC-timestamps:
   - `open` = первый доступный снимок линии (пробинг нескольких lookback-точек);
   - `close` = последний доступный перед `commence_time` матча;
   - Хранить `open_snapshot_utc`, `close_snapshot_utc` (фактическое время запроса);
   - Хранить `open_minutes_before`, `close_minutes_before` (от `commence_time`);
   - Убрать зависимость от `backfill.open_snapshot_utc` / `close_snapshot_utc` в конфиге.

### Текущее состояние (R19/R20 done)

- `OddsApiClient` (client.py) — REST, квота, кэш, retry.
- `backfill.py` — per-day: два fixed-timestamp запроса (`12:00`, `23:30`), Pinnacle only.
- `enrichment.py` — извлечение h2h (home/away/draw) + totals (**только over-price**, без `point`). `_totals_over_under` → `(over_price, under_price)`, `point` игнорируется.
- `store.py` — Parquet, upsert по `(game_date, home, away)`, 12 колонок (V1 schema).
- `refresh.py` — инкрементальный refresh, checkpoint, auto-merge в source.csv.
- `team_name_registry.py` — alias → canonical.
- Конфиг: `the_odds_api.yaml` (один `primary: pinnacle`, global `output_columns`).

### Что меняется

| Аспект | R20 (as-is) | R21 (to-be) |
|--------|-------------|-------------|
| Букмекеры | Pinnacle only | Pinnacle + 1xBet (onexbet) |
| Рынки Pinnacle | h2h (неявно OT) | h2h = winner incl OT (явно) |
| Рынки 1xBet | — | h2h = 1X2 regulation (draw) |
| Totals line/point | Не хранится | Хранится (`*_total_line_open/close`) |
| Totals prices | Только over-price | over + under prices |
| Snapshot open | Hardcoded `12:00 UTC` | Динамический: earliest available (probe schedule) |
| Snapshot close | Hardcoded `23:30 UTC` | Динамический: `commence_time − margin` |
| Время до матча | Не хранится | `*_minutes_before` (open/close) |
| `commence_time` | Не хранится | Хранится в store |
| Store schema | V1 (12 cols) | V2 (~36 cols) |

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| **Квота API при dynamic snapshots**: probe schedule (3–5 lookback-точек на день) × 2 bookmakers × ~900 дней = значительно больше запросов, чем 2/день в R20 | 🔴 Высокая | Кэш на диск (R19); один запрос возвращает все bookmakers → no per-bookmaker cost; группировка probe по `commence_time`; `quota_budget_per_run`; прогон по частям |
| **1xBet (onexbet) недоступен в историческом API**: часть дат / событий может не иметь 1xBet odds | 🟡 Средняя | Graceful NULL для отсутствующего bookmaker; coverage-метрика per-bookmaker; логирование пропусков |
| **Неоднозначность market semantics**: h2h для Pinnacle = 2-way (OT), для 1xBet = 3-way (regulation) — обе под ключом `h2h` в API | 🟡 Средняя | Семантику определять по bookmaker profile (конфиг), не по market key API; валидация: если у Pinnacle NHL есть outcome "Draw" — это аномалия, логировать |
| **Миграция V1→V2 store**: существующий `pinnacle_odds.parquet` не содержит total line, snapshot times, 1xBet cols | 🟡 Средняя | Миграционная функция: rename существующих колонок, добавить новые с NULL; re-backfill для заполнения |
| **`pinnacle_total_open`/`close` в source.csv**: переименование/расширение может сломать downstream consumers | 🟡 Средняя | Backward-compat: старые колонки остаются алиасами → deprecation notice; в source.csv добавить новые рядом |
| **Lookup window для open snapshot**: при large lookback (7 дней) API может возвращать odds для events, которых ещё не было (future events) — false positives | 🟢 Низкая | Фильтрация по `commence_time` events: брать только те, у которых `commence_time` совпадает с target date |

## Архитектурные решения

### 1. Snapshot timing — per-event, shared across bookmakers

Один запрос к The Odds API historical endpoint возвращает ALL bookmakers для ALL events на указанный `date` (ISO timestamp). Значит:
- `open_snapshot_utc` и `close_snapshot_utc` — **общие** для всех bookmakers в одном event.
- Individual bookmaker columns могут быть NULL, если bookmaker отсутствует в ответе.
- Timing columns: per-event, не per-bookmaker (экономия ~8 колонок).

### 1.1 Naming contract — market semantics in column names

В V2 вводим явную семантику в именах колонок/полей:
- `winner` и `total` = regulation only;
- `winner_withOT` и `total_withOT` = full game (OT/SO included).

Для NHL в текущем scope:
- `onexbet` → `winner` / `total`;
- `pinnacle` → `winner_withOT` / `total_withOT`.

Это снимает неоднозначность API (`h2h`, `totals`) и фиксирует бизнес-смысл в схеме данных.

### 2. Probe schedule (open snapshot discovery)

Конфигурируемый список lookback-точек (часы до `commence_time`):
```yaml
snapshot_discovery:
  open_probe_offsets_hours: [168, 72, 24]  # 7d, 3d, 1d
  close_margin_hours: 1                    # 1h before commence_time
```

Алгоритм per game_date:
1. Определить `commence_time` всех events на этот день (из любого ответа API).
2. `earliest_start = min(commence_times)` для группировки.
3. **Close**: query at `earliest_start − close_margin_hours`.
4. **Open**: probe от самого далёкого offset; первый с данными — "открытие".
5. Кэш: историческое API → те же cache_key → без повторных HTTP при re-run.

Стоимость: 2–4 запроса/день (vs 2 в R20). Кэш минимизирует повторные затраты.

### 3. V2 store schema (36 columns)

```
game_date, home_team_norm, away_team_norm, commence_time_utc,
open_snapshot_utc, close_snapshot_utc,
open_minutes_before, close_minutes_before,

# Pinnacle (winner_withOT, total_withOT)
pinnacle_winner_withOT_home_open, pinnacle_winner_withOT_away_open, pinnacle_winner_withOT_draw_open,
pinnacle_winner_withOT_home_close, pinnacle_winner_withOT_away_close, pinnacle_winner_withOT_draw_close,
pinnacle_total_withOT_line_open, pinnacle_total_withOT_over_open, pinnacle_total_withOT_under_open,
pinnacle_total_withOT_line_close, pinnacle_total_withOT_over_close, pinnacle_total_withOT_under_close,

# 1xBet (winner, total in regulation)
onexbet_winner_home_open, onexbet_winner_away_open, onexbet_winner_draw_open,
onexbet_winner_home_close, onexbet_winner_away_close, onexbet_winner_draw_close,
onexbet_total_line_open, onexbet_total_over_open, onexbet_total_under_open,
onexbet_total_line_close, onexbet_total_over_close, onexbet_total_under_close,

fetched_at
```

### 4. Dedup keys

`ODDS_DEDUP_KEYS = ("game_date", "home_team_norm", "away_team_norm")` — без изменений. `commence_time_utc` — информативная колонка, не часть ключа (один и тот же матч имеет одно время старта).

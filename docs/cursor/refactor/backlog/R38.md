# R38. NHL: единый slug турнира (`nhl`) — данные, пайплайн, модели, TG

> **Статус:** 🟡 В работе
> **Приоритет:** 🔴 High
> **Сложность:** Medium–High

---

## Проблема

Сейчас исторически разведены два имени:

- **`nhl`** — данные: `conf/source/nhl.yaml`, `data/source/nhl/`, `data/processed/nhl`, публичный API «NHL».
- **`nhl_train`** — обучение / promoted-модели: `conf/tournament/nhl_train.yaml`, `models/nhl_train/…`, утренний DAG / `cron_refresh` / `make nhl-morning-*` по умолчанию.

Из-за этого одна операционная цель («одна команда по расписанию → данные → кэфы → фичи → предикты в TG») требует ментальной карты двух имён, symlink’ов или обходных `conf/source/nhl_train.yaml`. Пользователь хочет **один фиксированный slug на весь контур**.

**Принятое архитектурное решение (эпик):** канонический идентификатор турнира в репозитории и в операционных командах — **`nhl`**. Артефакты, сейчас лежащие под `models/nhl_train/`, переносятся (или копируются) под `models/nhl/…` с обновлением `deploy.yaml` / promote-контракта; Hydra-группа `tournament=nhl_train` **выводится из употребления** (тонкий deprecated-алиас на один релиз или удаление после миграции). MLflow-имена экспериментов могут смениться (`nhl__…` вместо `nhl_train__…`) — зафиксировать в runbook для существующих деплоев.

Альтернатива «всё в `nhl_train`» отклонена: публичный API и каталог `data/source/nhl` уже закреплены за `nhl`; перенос данных на `nhl_train` хуже для UX и документации.

## Решение

Добавлен опциональный цикл walk-forward по календарным месяцам после фазы инициализации (Optuna только на inner train, как сейчас). При `walk_forward.enabled: false` порядок шагов trainer не меняется.

**Интеграция:** `WalkForwardSlicer` строит маски train/test по месяцам; `WalkForwardRunner` для каждого шага создаёт модель с зафиксированными `best_params`, обучает на расширяющемся train, предсказывает OOS-месяц, опционально вызывает `BettingSimulator`, склеивает trace и считает агрегаты. В `trainer.py`: при WF пропускается одноразовая оценка на статическом holdout до FS; после FS запускается WF; итоговые `test_ml_metrics` / betting берутся из агрегата WF.

**Rework (после первого ревью):** блок `apply_selected_to_fit` больше не отключается при включённом WF — переобучение на отобранных колонках выполняется перед WF. При `wf_enabled` + `apply_selected_to_fit` поле `metrics_full` остаётся `None` (нет вводящих в заблуждение `test_full_*` без статического holdout); флаг `apply_selected_column_refit` сохраняет теги MLflow `primary_feature_set=selected`, `fs_fit_applied=true`. Документация в `docs/source/walk_forward.rst`; тест `test_walk_forward_apply_selected_passes_subset_to_runner`.

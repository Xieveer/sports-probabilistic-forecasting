## Решение

Реализованы фазы 1–5 эпика R19. Полный NHL production-контур закрыт на уровне кода и инфраструктуры; операционные прогоны (обучение, materialize) отложены как R19.11–R19.12 (требуют запуска, не кода). Stretch-цели (R19.17–R19.20) остаются в бэклоге.

### Фаза 1 — Инкрементальный refresh (R19.1–R19.4)

- `NhlDataAssembler` получил режим `incremental=True`: при наличии `source.csv` определяется дата последнего завершённого матча, `date_from` смещается на 3 дня назад (буфер на корректировки статистики).
- Параметр `incremental: true/false` в `conf/source/nhl.yaml`.
- NHL добавлен в `SF_REFRESH_TOURNAMENTS` Airflow DAG (`dag_data_refresh.py`) с увеличенным `execution_timeout`.
- `conf/tournament/nhl.yaml` расширен: все FT/MT-статы (SOG, hits, PIM, 2PIM, BS, FOW), standings (conference_standing, P, GP), game_type, match_end, season.
- `conf/sport/ice_hockey.yaml`: добавлены `column_mapping` и `dtype_mapping` для новых колонок.
- `sports_forecast/validation/schemas.py`: Pandera-схема расширена NHL-колонками.
- `dvc.yaml`: NHL включён в `features` multirun.

### Фаза 2 — The Odds API (R19.5–R19.7)

- `OddsApiClient` (`sports_forecast/data/providers/odds/client.py`): requests-based, API key из `ODDS_API_KEY`, quota tracker (headers `x-requests-remaining`/`x-requests-used`), rate limiting, retry (429/5xx), кэширование ответов в JSON.
- `backfill.py`: идемпотентная стратегия на окно 2–3 сезонов, batching по дате, кэш на диск, CLI.
- `enrichment.py`: merge odds → source.csv по game_date + teams. Колонки кэфов (pinnacle_*) не передаются в FeaturePipeline.
- `conf/bookmaker/the_odds_api.yaml`: конфиг провайдера.
- Политика зафиксирована: odds только для валидации/бенчмарка.

### Фаза 3 — NHL-специфичный feature engineering (R19.8–R19.10)

- `NhlScheduleFeatureGenerator`: schedule density, rest/fatigue (`days_since_last_game`, `games_in_last_7/14d`, `is_back_to_back`, `rest_advantage`).
- `NhlStandingsFeatureGenerator`: standings-рейтинги (`conf_rank_diff`, `points_pct*`, `recent_form_5*`).
- `NhlRosterFeatureGenerator`: roster-фичи (roster_size, avg_player_age, num_forwards/defensemen/goalies).
- Конфиги генераторов: `conf/features/generators/{schedule,standings,roster}/nhl.yaml`.

### Фаза 5 — Telegram-бот (R19.13–R19.16)

- Пакет `sports_forecast/bot/` (aiogram 3): dispatcher, два middleware (`InjectConfigMiddleware`, `AllowedUsersMiddleware`), три роутера.
- **Rework fix:** `AllowedUsersMiddleware` извлекает `user_id` через `isinstance(event, (Message, CallbackQuery))` (не через `Update.from_user`, которого нет в aiogram 3). Зарегистрирован отдельно на `dp.message` и `dp.callback_query`.
- Команды `/start`, `/help` (R19.13), `/predict`, `/upcoming` с inline-клавиатурой (R19.14), `/status`, `/refresh`, `/models` с admin-guard (R19.15).
- Деплой: `deploy/sports-forecast-bot.service` (systemd), `make bot-dev`, `make bot-up` (R19.16).
- `conf/bot.yaml`: token из `BOT_TOKEN`, whitelist, admin_user_ids, api_base_url, airflow params.
- Тесты: `tests/test_bot.py` (3 теста: Message-block, CallbackQuery-block, Message-pass).

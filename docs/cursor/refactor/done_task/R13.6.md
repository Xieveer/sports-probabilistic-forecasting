# R13.6. Разделить read-only API и операционные endpoint-ы

> **Статус:** ✅ Выполнено

> **Сложность:** Medium
> **Выполнено:** 2026-04-04

---

## Задача

Разделить read-only API и операционные endpoint-ы (cache/stale) на уровне контракта и документации, чтобы не размывать SLA публичного слоя.

---

## Решение

Единый `router` в `predictions.py` разделён на два APIRouter:

- **`public_router`** (префикс `/predict`, тег `predictions`) — публичные read-only методы выдачи предсказаний из витрины; к ним относится целевой SLA по latency и доступности.
- **`operations_router`** (префикс `/internal/predict`, тег `operations`) — операционные endpoint-ы: LRU-кеш (`/cached/{match_id}`, `/cache/stats`, `/cache/clear`) и stale-лист для планировщика (`/stale`); вне публичного SLA, предназначены для внутренних клиентов.

В `app.py` добавлены `openapi_tags` (health / predictions / operations) с описанием SLA-разграничения; description приложения явно указывает два слоя. Оба роутера подключены через отдельные `include_router`.

В `service_orchestration_architecture.md` добавлена таблица префиксов/тегов/SLA, пояснение разницы поля `status` в ответе и `GET /internal/predict/stale`, обновлена секция «Компоненты платформы».

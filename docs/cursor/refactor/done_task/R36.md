## Проблема

После реализации walk-forward (R34) и block bootstrap (R35) нужно **прогнать все турниры** проекта под двумя режимами:

- **Scheme A (baseline):** фиксированный holdout, **walk-forward выключен**. В сетке ниже **bootstrap по умолчанию не задан** (остаётся выключенным), чтобы не смешивать сравнение с историческими point-оценками. Если нужны **доверительные интервалы по симуляции ставок** на том же статическом test — используйте **Scheme A+Bootstrap** (те же overrides `betting.bootstrap.*`, что и в Scheme B; `walk_forward.enabled` не трогаем или явно `false`).
- **Scheme B (walk-forward + bootstrap):** **`hyper=optuna`** на фазе init → лучшие гиперы → walk-forward на **`reuse_optuna_params`** (см. `conf/walk_forward.yaml`) без повторного Optuna на каждом шаге → block bootstrap на **агрегированном** cumulative `bet_trace`.

Этот эпик — **операционный чеклист** с готовыми CLI-командами. Код в R36 **не пишется** — зависимость от R34+R35 (конфиг-ключи, Hydra overrides).

### Допущения

- Группы `walk_forward` и `betting` подключены в `conf/config.yaml` defaults; переопределения задаются **без** ведущего `+`.
- Если точные имена Hydra-ключей изменятся после доработок R34/R35 — обновите блок **R36.1 Финальные overrides** ниже и сетку команд.
- Не все турниры имеют odds (беттинг-метрики недоступны без `betting.enabled: true` + наличия коэффициентов); помечаем это в сетке.
- **Feature selection:** в командах экспериментальной матрицы **не переопределяется** (`feature_selection=aggressive` и т.п. отсутствуют); используется профиль из `conf/config.yaml` / `feature_selection=default`.

## R36.1 Финальные overrides (без `+`)

Группа `walk_forward` (`conf/walk_forward.yaml`, `# @package walk_forward`):

| Ключ | Значение (production) |
|------|------------------------|
| `walk_forward.enabled` | `true` (Scheme B) |
| `walk_forward.frequency` | `month` |

Группа **`hyper`** (в `conf/config.yaml` по умолчанию **`hyper: none`** → без Optuna):

| Ключ / CLI | Значение (Scheme B — фаза init с Optuna) |
|------------|---------------------------------------------|
| выбор пресета | **`hyper=optuna`** → `conf/hyper/optuna.yaml` (`enabled: true`, `n_trials`, …). |

Без **`hyper=optuna`** Optuna **не запускается**, даже при `algorithm=catboost_reg` / `lgbm_reg` и непустом `optuna_space` — в логе будет `Optuna оптимизация отключена (hyper.enabled=false)`. Дальше walk-forward (если включён) идёт на **дефолтных** параметрах из YAML алгоритма. Для **`dummy`** при `hyper=optuna` Optuna всё равно пропускается (`optuna_space: null`).

Группа `betting` / вложенный блок `bootstrap` (`conf/betting.yaml`):

| Ключ | Значение (production) |
|------|------------------------|
| `betting.bootstrap.enabled` | `true` (когда нужны CI по беттинг-метрикам: Scheme **A+Bootstrap** или Scheme **B**) |
| `betting.bootstrap.n_resamples` | `5000` |

**Smoke:** для ускорения допустимо `betting.bootstrap.n_resamples=100` (CI / ручная проверка ключей).

**Где читается trace:** при `walk_forward.enabled=false` бутстрап в `trainer.py` берёт **`bet_trace_csv_path`** с обычного test-прогона; при `walk_forward.enabled=true` — **cumulative** trace из `WalkForwardResult`.

### Прогоны верификации (NHL только)

| Проверка | Команда (суть) | Результат |
|----------|----------------|------------|
| `--cfg job --resolve` Scheme A | `… algorithm=dummy features=advanced --cfg job --resolve` | OK |
| Короткий train Scheme A | `… algorithm=dummy features=advanced` | OK (обучение завершено) |
| `--cfg job --resolve` Scheme B + WF + bootstrap | `hyper=optuna algorithm=catboost_reg … walk_forward.enabled=true … betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100 --cfg job --resolve` | OK (`bootstrap.enabled: true`, `n_resamples: 100`) |

## R36.2 Command grid

### Обозначения и алгоритмы

**Scheme A (классификация на holdout, без WF):**

- **Bootstrap:** в минимальной сетке команд Scheme A **нет** — это осознанно (см. «Проблема»). Для **оценки беттинг-метрик с CI** добавьте к любой команде Scheme A строки `betting.bootstrap.enabled=true betting.bootstrap.n_resamples=5000` (раздел **Scheme A+Bootstrap**).
- **`catboost`** — основной gradient boosting (CatBoost).
- **`lgbm`** — LightGBM из группы конфигов `algorithm`.
- **`logreg`** — логистическая регрессия (быстрый линейный baseline).
- **`dummy`** — baseline по частотам классов; **обязателен** как референс.
- **`stacking`** — *опционально*, если включён соответствующий пресет и зависимости (см. `conf/algorithm/stacking.yaml`, цели sweep в Makefile / `docs/cursor/context`); в минимальной матрице R36 не требуется.

**Scheme B (WF + block bootstrap после агрегации trace):**

- **`hyper=optuna`** — **обязательно** для задуманной фазы init: иначе подбор гиперпараметров не выполняется (дефолт `hyper: none`).
- **`catboost_reg`**, **`lgbm_reg`** — пресеты с `optuna_space`; без `hyper=optuna` используются только статические `params` из YAML.
- **`dummy`** — тот же baseline на WF-пути (**обязателен**); при несовместимости с отдельными шагами WF смотреть лог trainer — при необходимости уточнить у maintainer.

**Фичи:** `<features>` = `advanced` для NHL; для остальных турниров — как в их `conf/tournament/*.yaml` (часто `advanced` или дефолт пресета).

**Массовый перебор алгоритмов:** встроенный Hydra **`--multirun`** со списком через запятую, например `algorithm=catboost,lgbm,logreg,dummy` (отдельный пакет `hydra-zen` в зависимостях этого репозитория не подключён).

### Smoke (NHL only)

Турнир: `tournament=nhl_train market=winner_withOT market_spec=winner_withOT`.
Не задавать `feature_selection` в CLI — остаётся default из конфига.

```bash
# Sanity: резолв конфига без обучения
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=dummy features=advanced \
  --cfg job --resolve

# Короткий реальный прогон (baseline)
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=dummy features=advanced

# Scheme A — multirun по всем обязательным алгоритмам
uv run python -m sports_forecast.train --multirun \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  features=advanced \
  algorithm=catboost,lgbm,logreg,dummy

# Scheme A+Bootstrap — тот же holdout, CI по trace (smoke: n_resamples=100)
uv run python -m sports_forecast.train --multirun \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  features=advanced \
  algorithm=catboost,lgbm,logreg,dummy \
  betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100

# Scheme B — multirun: Optuna init + WF + bootstrap (smoke: n_resamples=100; prod: 5000)
uv run python -m sports_forecast.train --multirun \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  features=advanced hyper=optuna \
  algorithm=catboost_reg,lgbm_reg,dummy \
  walk_forward.enabled=true walk_forward.frequency=month \
  betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100

# То же Scheme B — только проверить композицию конфига (--cfg job --resolve можно добавить к любой строке выше)
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=catboost_reg features=advanced hyper=optuna \
  walk_forward.enabled=true walk_forward.frequency=month \
  betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100 \
  --cfg job --resolve
```

Для продакшн-отчётов замените `betting.bootstrap.n_resamples=100` на **`betting.bootstrap.n_resamples=5000`**.

## Проблема

После реализации walk-forward (R34) и block bootstrap (R35) нужно **прогнать все турниры** проекта под двумя режимами:

- **Scheme A (baseline):** текущий pipeline с фиксированным holdout-сплитом, без walk-forward — для воспроизведения текущих метрик и сравнения «было / стало».
- **Scheme B (walk-forward + bootstrap):** Optuna на инициализации → walk-forward rolling → block bootstrap на агрегированном `bet_trace` — для оценки стабильности ROI.

Этот эпик — **операционный чеклист** с готовыми CLI-командами. Код в R36 **не пишется** — зависимость от R34+R35 (конфиг-ключи, Hydra overrides).

### Допущения

- Группы `walk_forward` и `betting` подключены в `conf/config.yaml` defaults; переопределения задаются **без** ведущего `+`.
- Если точные имена Hydra-ключей изменятся после доработок R34/R35 — обновите блок **R36.1 Финальные overrides** ниже и сетку команд.
- Не все турниры имеют odds (беттинг-метрики недоступны без `betting.enabled: true` + наличия коэффициентов); помечаем это в сетке.
- **Feature selection:** в командах экспериментальной матрицы **не переопределяется** (`feature_selection=aggressive` и т.п. отсутствуют); используется профиль из `conf/config.yaml` / `feature_selection=default`.

## R36.2 Command grid

### Обозначения и алгоритмы

**Scheme A (классификация на holdout, без WF):**

- **`catboost`** — основной gradient boosting (CatBoost).
- **`lgbm`** — LightGBM из группы конфигов `algorithm`.
- **`logreg`** — логистическая регрессия (быстрый линейный baseline).
- **`dummy`** — baseline по частотам классов; **обязателен** как референс.
- **`stacking`** — *опционально*, если включён соответствующий пресет и зависимости (см. `conf/algorithm/stacking.yaml`, цели sweep в Makefile / `docs/cursor/context`); в минимальной матрице R36 не требуется.

**Scheme B (WF + block bootstrap после агрегации trace):**

- **`catboost_reg`** — пресет CatBoost с отдельным Optuna search space (изолированное имя study).
- **`lgbm`** — LightGBM с `optuna_space` из `conf/algorithm/lgbm.yaml` (для второго бустинга на Scheme B; **`lgbm_reg` в этой матрице не задаём**).
- **`dummy`** — тот же baseline на WF-пути (**обязателен**); при несовместимости с отдельными шагами WF смотреть лог trainer — при необходимости уточнить у maintainer.

**Фичи:** `<features>` = `advanced` для NHL; для остальных турниров — как в их `conf/tournament/*.yaml` (часто `advanced` или дефолт пресета).

**Массовый перебор алгоритмов:** встроенный Hydra **`--multirun`** со списком через запятую, например `algorithm=catboost,lgbm,logreg,dummy` (отдельный пакет `hydra-zen` в зависимостях этого репозитория не подключён).

### Smoke (NHL only)

Турнир: `tournament=nhl_train market=winner_withOT market_spec=winner_withOT`.
Не задавать `feature_selection` в CLI — остаётся default из конфига.

```bash
# Sanity: резолв конфига без обучения
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=dummy features=advanced \
  --cfg job --resolve

# Короткий реальный прогон (baseline)
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=dummy features=advanced

# Scheme A — multirun по всем обязательным алгоритмам
uv run python -m sports_forecast.train --multirun \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  features=advanced \
  algorithm=catboost,lgbm,logreg,dummy

# Scheme B — multirun: WF + bootstrap (smoke: n_resamples=100; prod: 5000)
uv run python -m sports_forecast.train --multirun \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  features=advanced \
  algorithm=catboost_reg,lgbm,dummy \
  walk_forward.enabled=true walk_forward.frequency=month \
  betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100

# То же Scheme B — только проверить композицию конфига (--cfg job --resolve можно добавить к любой строке выше)
uv run python -m sports_forecast.train \
  tournament=nhl_train market=winner_withOT market_spec=winner_withOT \
  algorithm=catboost_reg features=advanced \
  walk_forward.enabled=true walk_forward.frequency=month \
  betting.bootstrap.enabled=true betting.bootstrap.n_resamples=100 \
  --cfg job --resolve
```

Для продакшн-отчётов замените `betting.bootstrap.n_resamples=100` на **`betting.bootstrap.n_resamples=5000`**.

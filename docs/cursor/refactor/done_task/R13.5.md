# R13.5. Декомпозиция refresh-контура по турнирам + политика конкуренции

> **Статус:** ✅ Выполнено
> **Приоритет:** 🔴 High
> **Сложность:** Medium
> **Выполнено:** 2026-04-02

---

## Решение

Для `data_refresh` реализован по-турнирный fail-fast контур обновления с обязательной
последовательностью стадий `source → ingest → clean → features → materialize`.

Добавлен отдельный builder shell-команды refresh-пайплайна с поддержкой source-stage
контракта в двух режимах: шаблон с `{tournament}` (предпочтительный) и legacy-передача
турнира позиционным аргументом. В DAG зафиксирована политика конкуренции через
`pool`, `lock` и лимиты `max_active_runs/max_active_tasks`.

# R17. NHL Web API — провайдер данных для сбора матчевой статистики

> **Статус:** ✅ Выполнено
> **Приоритет:** 🔴 High
> **Сложность:** High
> **Выполнено:** 2026-04-05

---

## Проблема

Проект расширяется на реальный хоккей (NHL). Датасет описан в `docs/cursor/source_data/nhl.md` (с сезона 2000): id, season, game type, datetime, location, teams, match_end (REG/OT/SO), scores MT/FT, SOG/BS/hits/PIM/2PIM/FOW, rosters + injuries, conference standing + P + GP до игры.

Публичный **NHL Web API** (`api-web.nhle.com/v1/`) документирован в `docs/cursor/source_data/nhl_web_api.md`. Данные доступны бесплатно, но API неофициальный: без гарантий стабильности контракта, требует `User-Agent`, может блокировать при агрессивных запросах.

R14 ввёл паттерн `SourceProvider`. Для NHL нужна отдельная реализация: множество эндпоинтов, итерация по датам, агрегация JSON → плоская таблица.

**Цель:** новый провайдер `nhl_web_api`, который собирает матчи и статистику, подтягивает standings и rosters, формирует `source.csv` для ingest/clean и регистрируется в `ProviderRegistry`.

---

## Решение

Реализован подпакет `sports_forecast/data/providers/nhl/`:

- **`client.py`** — `NhlApiClient`: `requests.Session`, настраиваемый `User-Agent`, `urllib3.Retry` (429/5xx), минимальный интервал между запросами `min_delay_sec`.
- **`schedule.py`** — обход `schedule/{YYYY-MM-DD}` с шагом 7 дней, дедуп по `game_id`, фильтры `season_id_min/max`, `finished_only`; для старых ответов без `gameDate` используется дата недели или префикс `startTimeUTC`.
- **`boxscore.py`** — boxscore + при включённом флаге play-by-play: счёт FT из команд boxscore, MT-голы и событийные метрики из PBP; SOG FT официальные из boxscore; PIM FT — сумма по карточке матча (игроки); 2PIM из штрафов PBP (`MIN`, duration 2 или 4); без PBP — fallback bs/hits из сумм скейтеров.
- **`standings.py`** — `standings/{date}` → `conferenceSequence`, `points`, `gamesPlayed` по аббревиатуре команды.
- **`roster.py`** — `roster/{abbr}/{season}` → JSON-строка со списком игроков; `injured: []` (отдельного фида в Web API нет).
- **`assembler.py`** — кэш standings по дате игры, кэш ростеров по (команда, сезон), опциональный checkpoint (`checkpoint_file`), лимит `max_games`.
- **`provider.py`** — `NhlWebApiSourceProvider.fetch()` → `data/source/<name>/source.csv`.

Зарегистрировано `provider.type: nhl_web_api` в `registry.py`, экспорт в `providers/__init__.py`. Добавлены `conf/sport/ice_hockey.yaml`, `conf/source/nhl.yaml`, `conf/tournament/nhl.yaml`, каталог `data/source/nhl/`, описание в `HOW_TO_ADD_NEW_TOURNAMENT.md`. В `dvc.yaml` у этапа ingest добавлен комментарий про NHL и про то, что `features` multirun по умолчанию не включает `nhl`. Юнит-тесты: `tests/test_nhl_provider.py` (логика без сети).

Отложено вне скоупа приёмки: коэффициенты БК (отдельный источник); полноценный injury report; отдельные JSON-файлы фикстур вместо инлайновых dict в тестах; расширение `dvc repro features` на `nhl` при наличии данных.

## Риски (сохраняются)

1. Нестабильность неофициального API.
2. Большой объём HTTP при полной истории; нужен контроль `max_games` / checkpoint.
3. Старые сезоны — неполные boxscore/PBP.
4. Standings на `gameDate` — приближённый «снимок до игры», не микроскопическая точность.

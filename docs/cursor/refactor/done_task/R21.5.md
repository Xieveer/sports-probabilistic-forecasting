## Задача

Интегрировать `discover_snapshots_for_day` (R21.4) в `backfill_day_frames`, добавить timing-колонки в DataFrame, реализовать legacy fallback через флаг `--legacy-timestamps`. Является подзадачей **R21** (backlog/R21.md).

---

## Решение

В `sports_forecast/data/providers/odds/backfill.py` реализованы четыре ветки логики (`use_open_close × legacy_timestamps`):

| `use_open_close` | `legacy_timestamps` | Поведение |
|---|---|---|
| `True` | `False` (default) | `discover_snapshots_for_day` → два снимка open/close |
| `True` | `True` | Два фиксированных ISO из `backfill.open/close_snapshot_utc` |
| `False` | `False` | `discover_snapshots_for_day` → только open-снимок |
| `False` | `True` | Один фиксированный ISO (open) |

Добавлены вспомогательные функции:
- `_book_get` — унифицированный доступ к `dict` / `DictConfig`;
- `_snapshot_discovery_params` — безопасное извлечение `open_probe_offsets_hours`, `close_margin_hours` из `snapshot_discovery` YAML-секции с fallback-дефолтами;
- `_attach_snapshot_timing` — добавляет `open_snapshot_utc`, `close_snapshot_utc`, `open_minutes_before`, `close_minutes_before` из `SnapshotPlan`;
- `_legacy_day_snapshot_isos` — строит ISO для legacy-режима (поддержка как `"HH:MM:SS"`, так и полных ISO).

Multi-bookmaker extraction работает прозрачно: `events_to_odds_frame(..., book_cfg=book_root)` → если в конфиге есть `bookmaker_profiles`, активируется V2-путь (R21.3). Параметр `legacy_timestamps` прокинут через `_backfill_date_range`, `run_backfill` и CLI-аргумент `--legacy-timestamps`.

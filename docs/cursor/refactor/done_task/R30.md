## Проблема

В `test_bet_trace.csv` колонка «победа `pl` по голам» не совпадала с `y_true` (сотни строк на holdout). Риск: неверный таргет ломает обучение и беттинг-метрики.

---

## Решение

**Корневая причина:** в `SingleExperimentRunner._train_model` после сортировки `df` по времени таргет не переиндексировался по тому же порядку строк. Конструкция `target.iloc[df.index]` после `reset_index(drop=True)` давала `iloc[0:n]` — **первые n значений старого таргета**, без соответствия отсортированным строкам.

**Исправление:** `sort_order = df.sort_values(time_col).index`, затем `df = df.loc[sort_order].reset_index(drop=True)` и `target = target.loc[sort_order].reset_index(drop=True)` (коммит `fix(train): align target with df after time sort`).

**Регрессия:** `tests/test_trainer_target_sort_alignment.py` — демонстрирует ошибку старого паттерна и проверяет корректное выравнивание.

**Подзадачи R30.1–R30.4** из первоначального бэклога (колонка `target_from_goals` в CSV, assert при записи trace, интеграция по прочитанному CSV, заметка про Excel) **не реализованы** — закрыты как необязательный техдолг (см. `backlog/reviewer-tech-debt.md`, блок 2026-05-09 про R30 follow-ups). Основной критический дефект устранён.

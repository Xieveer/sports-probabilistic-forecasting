# R39.2 — Общий модуль сравнения pred vs live Pinnacle (вне FastAPI route)

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-05-13
> **Приоритет:** 🔴 High (в составе эпика R39)
> **Сложность:** Medium

---

## Решение

Чистая логика полей live Pinnacle moneyline (`pinnacle_*`, `edge_home`, `bet_decision_home`, `live_odds_status`) вынесена в модуль `sports_forecast.betting.live_moneyline_extras`: функции `build_live_moneyline_extras`, `proba_home_from_prediction`, `nhl_live_match_ref_from_prediction`, `match_dt_utc` и контракт `LiveMoneylinePredictionInput` (Protocol). Формулы повторно используют `compute_edge` и `decide_bet` из `edge_decision`.

`sports_forecast.service.live_odds_enrichment` переведён на импорт этого модуля вместо дублирующих приватных хелперов `_compute_extras_for_pred`, `_proba_home`, `_pred_to_ref`.

Добавлены unit-тесты `tests/test_live_moneyline_extras.py` (граничные случаи статусов, частичная линия, паритет с прямым вызовом build при тех же входах, что у enrichment). Существующие тесты `tests/test_live_odds_enrichment.py` проходят без регрессий.

## Проблема (из эпика R39)

Логика edge/decision против live Pinnacle не должна жить только в HTTP-слое; оркестрация и digest должны импортировать ту же реализацию без зависимости от FastAPI.

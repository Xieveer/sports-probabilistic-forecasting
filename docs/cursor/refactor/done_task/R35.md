# R35. Block bootstrap на финальном списке ставок

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-05-11
> **Приоритет:** 🔴 High
> **Сложность:** Medium

---

## Решение

Реализован модуль `sports_forecast/betting/bootstrap.py` с классом `BlockBootstrap`
(circular block resampling по Politis–Romano) и датаклассами `BootstrapResult` /
`MetricBootstrapStats`. Длина каждого блока семплируется равномерно из
`[min_block_length, max_block_length]` (random block length — снижает
чувствительность к фиксированному размеру); при достижении конца массива
ставки «заворачиваются» (модуль по `n`).

**Вычисляемые метрики:** `roi`, `profit_units`, `n_bets`, `sharpe_like`,
`max_drawdown_pct`, `hit_rate` — доверительные интервалы (percentile bootstrap)
на уровне `confidence_level` (по умолчанию 0.95).

**Интеграция в trainer.py:** метод `_log_block_bootstrap_if_enabled` вызывается
после `_log_walk_forward_to_mlflow`. Выбор trace-источника:

- `walk_forward.enabled: true` → `WalkForwardResult.cumulative_bet_trace_path`
- `walk_forward.enabled: false` → `business_metrics["bet_trace_csv_path"]`

Graceful skip с `logger.warning` при любой нехватке данных (trace не найден,
нет размещённых ставок, ошибка чтения CSV).

**MLflow:** теги `bootstrap_enabled`, `bootstrap_n_resamples`,
`bootstrap_block_length_range`; метрики `bootstrap_roi_mean/ci_lower/ci_upper`,
аналогично для `profit_units` и `sharpe_like`; артефакт `bootstrap_summary.csv`.

**По умолчанию `enabled: false`** — нулевое изменение времени train.

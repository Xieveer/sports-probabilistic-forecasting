## Решение

Добавлен Airflow DAG `nhl_morning_refresh` (`schedule="0 9 * * *"` в UTC по умолчанию = **09:00 UTC** = **12:00 MSK**). Пайплайн — тот же контракт, что у `data_refresh`: `build_refresh_per_tournament_command` (**source** с инкрементальным odds post-step при `odds.enabled` в source-конфиге → ingest → clean → features → **materialize** для `winner_withOT` / `nhl_train` по умолчанию), затем **validate**. Используются те же **pool**, **flock** и дефолты конкуренции, что у `dag_data_refresh` (`SF_REFRESH_POOL`, `SF_REFRESH_LOCK_FILE`, `SF_REFRESH_LOCK_WAIT_SECONDS`); лимиты параллелизма DAG переопределяются отдельными переменными `SF_NHL_MORNING_MAX_ACTIVE_RUNS` / `SF_NHL_MORNING_MAX_ACTIVE_TASKS` (оба по умолчанию 1).

В `docs/source/nhl_local_operations.rst` задокументированы эквивалент времени (MSK + UTC), шаблон хостового cron с `CRON_TZ=Europe/Moscow`, переменные Airflow для переопределений. В Makefile — цель **`nhl-morning-refresh-dry-run`** (печать той же shell-цепочки, что выполняет DAG/cron, через `cron_refresh --dry-run`). В docstring `cron_refresh.py` — указатель на DAG и runbook.

# R13. Выравнивание реализации с Service & Orchestration Architecture

> **Статус:** ✅ Выполнено
> **Приоритет:** 🔴 High
> **Сложность:** Medium
> **Выполнено:** 2026-04-04

---

## Проблема

Текущая реализация в целом следовала целевой схеме "API читает, пайплайны считают", но имелось несколько расхождений с архитектурным контрактом из `service_orchestration_architecture.md`.

Критичные точки: `data_refresh` не включал явный этап `validate`, материализация опиралась на локальную файловую структуру моделей вместо явного контракта с promoted-артефактом, а `training_sweep` использовал единый `promote_best` для потенциально мульти-турнирного запуска. Дополнительно отсутствовал формализованный operational-контракт по DVC runtime между окружениями.

---

## Что было сделано

- [x] **R13.1** Добавлен этап валидации в `data_refresh` DAG (`ingest → clean → features → validate`) и зафиксировано fail-fast поведение.
- [x] **R13.2** Введён явный прод-контракт materialize: использует артефакт promoted-модели (`deploy.yaml`/метаданные), а не только `algorithm/features` из переменных DAG.
- [x] **R13.3** Исправлен `training_sweep` для мульти-турнирного режима: promote выполняется по каждому турниру/эксперименту отдельно.
- [x] **R13.4** Зафиксирован operational-контракт DVC по средам (prod/dev/CI): где разрешены прямые вызовы модулей, где обязателен `dvc repro`, как синхронизируются артефакты.
- [x] **R13.5** Декомпозирован контур обновления по турнирам без пропуска обязательных стадий: для изменённого турнира запускается `source → ingest → clean → features → materialize`, определена политика конкуренции (pool/lock/max_active_runs).
- [x] **R13.6** Разделены read-only API и операционные endpoint-ы (cache/stale) на уровне контракта и документации.
- [x] **R13.7** Добавлены smoke/integration проверки оркестрации (DAG-команды + CLI связка train/promote/materialize) как acceptance для архитектурного контура.

---

## Решение (сводка)

Все 7 подзадач R13 выполнены. Архитектурный контур полностью выровнен с `service_orchestration_architecture.md`:
- DAG `data_refresh` теперь явно включает `validate`-этап с fail-fast.
- Materialize использует promoted-артефакт через `deploy.yaml`.
- `training_sweep` запускает promote per-tournament.
- DVC runtime-контракт задокументирован по средам.
- Refresh-контур декомпозирован с политикой конкуренции.
- API разделён на публичный и операционный слои.
- Добавлены 7 smoke/integration тестов принятия для всего оркестрационного контура.

## Решение

Расширена `PredictionResponse` (`sports_forecast/service/schemas.py`): `pinnacle_home_decimal`, `pinnacle_away_decimal`, `edge_home`, `bet_decision_home`, `live_odds_status` (описания для OpenAPI). Единый контракт для `GET /predict/{match_id}`, `GET /predict/{match_id}/all`, `GET /predict/upcoming/{tournament}` через `_to_response` + опциональные kwargs из `batch_live_response_extras`. Реализован модуль `sports_forecast/service/live_odds_enrichment.py`: один батч-вызов к слою R37.4 (`fetch_nhl_pinnacle_quotes_for_refs`) на список строк витрины при `live_pinnacle=true`, пороги edge — `load_edge_decision_params` из `conf/service_api.yaml`; для не-NHL / не-moneyline — статусы `skipped_*`, без HTTP; `live_pinnacle=false` — `disabled`; нет ключа API — `missing_api_key`; ошибка сети/квоты — `fetch_failed`. Query-параметр `live_pinnacle` с дефолтом `true` на перечисленных эндпоинтах. Кэшированный внутренний ответ (`get_prediction_cached`) явно заполняет новые поля `None`. Политика **train-time `odds_raw` vs live decimal в ответе API** зафиксирована в `docs/cursor/context/service_orchestration_architecture.md` (Runtime-границы + блок в «Inference-стратегия»); миграция БД под отдельный снапшот live не вводилась. Юнит-тесты: `tests/test_live_odds_enrichment.py`. В `conf/service_api.yaml` — комментарий о связи edge-параметров с live-ответами.

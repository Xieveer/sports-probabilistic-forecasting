# R37.7 — Telegram: обогащённый payload (live Pinnacle, edge, bet/no-bet)

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-05-13
> **Приоритет:** 🔴 High (в составе эпика R37)
> **Сложность:** Low

---

## Решение

Обработчик `sports_forecast/bot/handlers/predict.py` для `/predict` и `/upcoming` строит запросы к `GET /predict/upcoming/{tournament}` с параметрами **`live_pinnacle=true`** (по умолчанию, из `conf/bot.yaml` → `bot.live_pinnacle`) и для турниров NHL (`nhl`, `nhl_*`) — **`market=winner_withOT`** и **`market_spec=winner_withOT`**, чтобы совпадать с материализованным рынком OT.

Добавлены `_format_live_lines` и использование в карточке прогноза и в тексте расписания: при **`live_odds_status=missing_api_key`** пользователь видит пояснение про **ODDS_API_KEY на стороне API** (бот не падает; API уже отдаёт статус без 5xx). При успешном обогащении — decimal Pinnacle, edge, решение на русском (`ставка` / `нет ставки` / `недостаточно данных`).

В **`conf/bot.yaml`**: ключ `live_pinnacle`, комментарии R37.7 в шапке и у ключа.

Юнит-тесты форматирования и параметров запроса: `tests/test_bot_predict_format.py`.

Планировщик **не** добавлялся (MVP без apscheduler; пересечение с R24.2 остаётся на стороне эпика R24).

## Альтернативы и ограничения

- **Альтернатива:** общий клиентский модуль для API вместо дублирования URL в трёх хендлерах — отложено ради минимального диффа.
- **Ограничение:** бот не читает `ODDS_API_KEY` сам; корректность live-блока полностью зависит от конфигурации сервиса API.

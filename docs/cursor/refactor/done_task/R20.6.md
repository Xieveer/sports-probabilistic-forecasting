# R20.6 — Валидация и наблюдаемость odds-данных

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-04-25
> **Приоритет:** 🔴 High
> **Сложность:** Medium

---

## Исходное требование

- Pandera-схема для odds-колонок в `schemas.py`: nullable float, диапазон 1.01–100.0.
- Coverage-метрика: `odds_coverage_pct = % строк source с non-null pinnacle_home_close`.
- Логирование в `refresh.py`: оставшаяся квота API, match rate (matched / total events), coverage.
- Warning при coverage < порога (конфиг `min_odds_coverage_pct`, default 70%).

---

## Решение

**Pandera-валидация (`schemas.py`):**

- `_PINNACLE_ODDS_FLOAT_COLS` — кортеж из 8 колонок `pinnacle_*` (open/close для home/away/draw/total).
- `_pinnacle_odds_in_valid_range(s)` — проверка диапазона `[1.01, 100.0]` с поддержкой NaN (nullable).
- `PinnacleOddsNumericSchema` — `DataFrameSchema` с `strict=False, coerce=True`: отсутствующие колонки не нарушают схему, coerce приводит числа к float.
- `validate_pinnacle_odds_float_columns(df, *, context)` — публичная функция: пустой df и отсутствующие колонки пропускаются; при нарушении диапазона бросает `RuntimeError(f"{context}: ...")` (fail-fast, оборачивает `SchemaError/SchemaErrors`).

Функция подключена в двух точках:
- `backfill.py` → `_upsert_if_non_empty()`: перед каждым upsert в store (context `"backfill:upsert"`).
- `refresh.py` → после итогового `load_odds_store()`: валидация store после backfill (context `"odds refresh: store after backfill"`).

**Наблюдаемость (`refresh.py`):**

- `BackfillRunResult` (в `backfill.py`) — dataclass с `frame`, `quota_hit`, `requests_remaining`, `requests_used`; `run_backfill` теперь возвращает его вместо голого DataFrame.
- `_normalize_backfill_out()` — совместимость с мок-функциями, возвращающими `pd.DataFrame`.
- `OddsRefreshResult` расширен полями `requests_remaining: int | None` и `requests_used: int | None`.
- В `refresh.py` логируется снимок квоты (последний ответ API) при `req_rem is not None or req_used is not None`.
- `_log_source_odds_metrics(source_csv, min_odds_coverage_pct, store_rows)` — читает source.csv, вычисляет `coverage = % non-null pinnacle_home_close`, логирует `source_rows`, `match_rate_vs_source_pct`, `odds_coverage_pct`, `store_rows`; при `coverage < min_odds_coverage_pct` — `logger.warning`.
- `_log_unmatched_report_metrics(report_path)` — считает строки unmatched_teams.csv, логирует число несоответствий.
- `resolve_path_under_tournament_source(project_root, tournament, configured, default_relative)` — резолвит путь: абсолютный — как есть, None/null/~ — default_relative.
- `_odds_runtime_from_source(source_name, tournament, project_root)` — расширена возвратом `(buf, max_days, auto_merge, p_store, p_state, p_unm, min_cov)`.

**`source_refresh.py`:** добавлен `api_remaining=%s` в финальный INFO-лог `_run_odds_post_fetch`.

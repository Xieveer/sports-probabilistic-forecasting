# R13.7. Smoke/integration acceptance для оркестрационного контура

## Что нужно было сделать

Добавить smoke/integration проверки оркестрации (DAG-команды + CLI связка train/promote/materialize) как acceptance для архитектурного контура: Makefile train/promote/materialize chain, CLI --help checks, DAG static/AST checks.

---

## Решение

Реализованы семь smoke/integration тестов без зависимости от запущенного Airflow (импорт `apache-airflow` в runtime не требуется):

1. **`test_makefile_wires_train_promote_materialize_cli`** — парсит `Makefile` regex-ом и проверяет, что `train:` вызывает `python -m sports_forecast.train`, `promote:` — `main.py promote compare`, `materialize:` — `python -m sports_forecast.materialize`.

2. **`test_hydra_entrypoints_help_succeeds`** — запускает `sports_forecast.train --help` и `sports_forecast.materialize --help` с минимальными Hydra-overrides и проверяет `returncode == 0`.

3. **`test_main_promote_compare_help_succeeds`** — вызывает `main.py promote compare --help`, проверяет exit code 0.

4-6. **`test_dag_source_contract`** (параметризован по `dag_data_refresh.py`, `dag_training.py`, `dag_monitoring.py`) — AST-разбор DAG-файлов: проверяет `dag_id`, набор `task_id` и порядок зависимостей (edge-подстроки в нормализованном исходнике без пробелов).

7. **`test_dag_materialize_source_contract`** — специальный кейс для `dag_materialize.py`: `task_id` формируется f-строкой, поэтому тест проверяет паттерн напрямую в тексте, а также наличие `SF_MATERIALIZE_TOURNAMENTS` и `sports_forecast.materialize`.

Вспомогательный модуль `orchestration_dag_ast.py` реализует AST-парсер DAG-файлов (`parse_dag_source_info`) и нормализатор исходника (`normalized_source_lines`) без импорта Airflow.

Все 7 тестов проходят: `7 passed in 4.65s`.

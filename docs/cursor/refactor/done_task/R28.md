# R28. Унификация rolling-контекстов через семантические алиасы колонок

> **Статус:** ✅ Выполнено
> **Приоритет:** 🟡 Medium
> **Сложность:** Medium
> **Выполнено:** 2026-05-04

---

## Проблема

Контексты в `context_library.yaml` содержат хардкод имён реальных колонок:
- `tour_num` → `keys: ["pl", "tour_num"]` (реальная колонка `tour_num` в данных)
- `match_num` → `keys: ["pl", "tour_match_num"]`
- `weekday` → `keys: ["pl", "weekday"]`

Это работает только если во всех спортах одинаковые имена колонок. Но семантика разная:

| Абстрактный контекст | Table Tennis / Cyberhockey | NHL |
|---|---|---|
| `tour_num` | внутри-дневной мини-турнир (3–8 матчей) | нет прямого аналога |
| `match_num` | номер матча в мини-турнире | номер игры в сезоне |
| `inseason` | не существует | группировка по `season` (82 игры) |

Для NHL нужен контекст `inseason` (сброс EWM при смене сезона), что требует
группировки по колонке `season`, которой нет в TT/cyberhockey. Кроме того,
если один и тот же абстрактный контекст должен маппиться на разные колонки
в разных спортах, текущая архитектура этого не поддерживает.

### Целевое состояние

Разделить **семантику контекста** (что означает, определяется в `context_library.yaml`)
и **конкретные колонки** (какая колонка реализует это понятие, определяется в `conf/sport/*.yaml`).

---

## Решение

Реализован **подход C (column-level alias)**: sport-конфиг задаёт
`rolling_column_aliases: { old_col: new_col }`. При сборке контекстов
`rolling_contexts.py` заменяет имена колонок в `keys`.

### Ключевые изменения

**`rolling_contexts.py`:**
- `_load_column_aliases(tournament_cfg)` — загружает `rolling_column_aliases` из конфига
  (поддерживает `dict`, `DictConfig`, `getattr`-fallback); warning на identity mapping
- `_resolve_keys(keys, aliases)` — заменяет имена через aliases; неизвестные ключи остаются
- `_build_ewm_context` / `_build_count_context` — принимают `aliases`, разрешают ключи,
  пишут DEBUG-лог `raw_keys → resolved_keys` per context
- `expand_rolling_generators_inplace` — загружает aliases, INFO-лог при наличии;
  рефакторинг цикла: теперь итерируется по **всем** генераторам с `context_source: library`
  (не хардкодированные ewm_diff/ewm_total/count), dispatch по `type == "ewm"/"count"`;
  ValueError на unknown type
- `_ewm_compute_diff_for_generator` — поддерживает новый override `library_compute_diff`,
  fallback к `endswith("_total")`
- `clear_rolling_context_library_cache()` — хелпер для тестов и hot-reload

**`context_library.yaml`:**
- Добавлен `inseason`: `keys: ["pl", "season"]`, `players: ["pl", "opp"]`
- Добавлен `h2h_inseason`: `keys: ["pl", "opp", "season"]`, `h2h: true`
- `canonical_order` обновлён: `inseason` после `form`, `h2h_inseason` после `h2h_form`

**`conf/sport/ice_hockey.yaml`:**
- `rolling_column_aliases: {}` (contract, season совпадает с library)
- Добавлены `inseason`, `h2h_inseason` в `rolling_context_names`
- Убраны `tour_num`, `match_num`, `h2h_match_num` (семантически неприменимы к NHL)

**`conf/sport/table_tennis.yaml`, `conf/sport/cyberhockey.yaml`:**
- Добавлен комментарий об опциональности `rolling_column_aliases`; поведение не меняется

**Backward compat:** при отсутствии `rolling_column_aliases` aliases = `{}`,
ключи используются as-is → все существующие спорты продолжают работать.

## Дизайн-решения

### Выбранный подход — column-level alias

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| **A) Placeholder-шаблоны** `{season_col}` в library keys | Явная связь | Ломает обратную совместимость, OmegaConf/Hydra сложности |
| **B) Context-level overrides** в sport config | Гибко | Дублирует структуру definitions, verbose |
| **C) Column-level alias** в sport config ✅ | Минимальный diff, один уровень индирекции, обратная совместимость | Потенциальная неоднозначность если одна колонка в разных семантиках |

# R20.3 — Инкрементальный odds refresh: логика определения нового диапазона дат

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-04-25
> **Приоритет:** 🔴 High
> **Сложность:** High

---

## Исходное требование

- Создать `sports_forecast/data/providers/odds/refresh.py`.
- Логика: загрузить OddsStore → `max(game_date)` → fetch odds от `(max_date - buffer_days)` до `today`.
- При пустом store — fallback на полный backfill текущего сезона.
- Параметры из конфига: `incremental_buffer_days`, `max_days_per_refresh`.
- Resume/checkpoint: `last_successful_date`, `in_progress_from`, `updated_at` в `data/source/{tournament}/odds/refresh_state.json`.
- При прерывании продолжать с `last_successful_date - buffer_days`, не перезагружая уже сохранённые в store данные (через upsert).
- Результат сохраняется в OddsStore + авто-merge в `source.csv` через `enrichment`.

---

## Решение

Реализован модуль `refresh.py` с явно разделёнными слоями:

**Планирование диапазона (`build_incremental_need_range`):**
- При непустом store: `need_from = max_game_date - buffer_days`; если у state есть `last_successful_date` — берётся `min(need_from, last_successful - buffer_days)` для безопасного перекрытия.
- При пустом store: берутся границы последнего сезона из `bookmaker.seasons.{tournament}` YAML, `need_to = min(season_to, today)`.

**Сегментация (`build_refresh_segment`):**
- Применяет `max_days_per_refresh` cap: если `need_to - need_from + 1 > cap`, диапазон разбивается на первый сегмент; `has_more=True` сигнализирует о наличии последующих.
- Resume: `in_progress_from` из state сдвигает `need_from` вперёд (`max(need_from, ip)`), пропуская уже обработанные дни.

**Checkpoint (`refresh_state.json`):**
- Перед вызовом backfill записывается state с `in_progress_from = seg.date_from` — crash marker.
- После успешного backfill: `last_successful_date = seg.date_to`, `in_progress_from = next_day` (если `has_more`) или `None` (если сегмент последний).
- Атомарная запись JSON через `.tmp` + `rename` — соответствует атомарности store.

**Идемпотентность:** backfill завершается через `upsert_odds_store_file` (R20.1), поэтому повторный прогон одного сегмента безопасен.

**Merge:** `merge_odds_into_source_csv` вызывается после upsert при `auto_merge=True` и наличии `source.csv`.

**Параметры:** читаются из `conf/source/{source_config_name}.yaml` → секция `odds` (`incremental_buffer_days`, `max_days_per_refresh`, `auto_merge`); fallback на константы.

## Решение

Основные MLflow-метрики после `apply_selected_to_fit` соответствуют shadow/prod на **отобранных** фичах; снимок прогона на полном наборе — ключи `*_full_*` и артефакт `feature_importance_full.csv`. В `aggressive` по умолчанию включено переобучение на подмножестве. Добавлен runbook Sphinx и теги `primary_feature_set`, `fs_round`. Итеративный FS вынесен в отложенный эпик **R32**.

---

## Результат

- **`conf/feature_selection/aggressive.yaml`**: `apply_selected_to_fit: true` по умолчанию.
- **`conf/feature_selection/default.yaml`**: комментарии про primary vs `*_full_*` (значение флага без изменений для `enabled: false`).
- **`sports_forecast/training/trainer.py`**: при `apply_selected_to_fit` основные `test_*` / `shadow_*` / betting / cal / `feature_importance.csv` — модель на **отобранных** фичах; снимок полного набора — `test_full_*`, `shadow_full_*`, `tscv_full_*`, префикс `full_` у беттинга, `cal_full_*`, `feature_importance_full.csv`. Теги: `primary_feature_set`, `fs_round`, сохранён `fs_fit_applied`.
- **`docs/source/feature_selection_workflow.rst`** + запись в toctree **`docs/source/index.rst`**: runbook и контракт итеративного FS (R31.4).

## Примечание по совместимости MLflow

Имена `*_fs_fit_*` и `feature_importance_fs_fit.csv` **заменены** на `*_full_*` и `feature_importance_full.csv`. Старые прогоны в реестре не меняются.

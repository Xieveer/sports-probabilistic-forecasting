- **Ops:** `scripts/refresh_smart_tables_catalog.py`; Makefile `football-catalog-refresh`, `football-backfill`, `football-backfill-wc`, `football-ingest-debug`.
- **DVC:** deps на модули smart_tables; комментарий про football_nationals вне features multirun.
- **Валидация:** опциональные football-колонки в `InterimSchema`; Pandera на ядро id/datetime/scores.
- **Тесты:** 10 offline-тестов (`tests/test_smart_tables_provider.py`), fixture WC final 314668, contract ingest+clean smoke.

**Не в scope (отложено):** R42.16 Airflow incremental DAG (stretch); Phase 2 features/train/sweep; historical odds merge.

## Проблема

Проект масштабируется на **футбол** с фокусом на **сборные** и подготовку к **ЧМ-2026**. Разведка Smart Tables завершена (`docs/cursor/source_data/smart_tables.md`): неофициальный backend `backend.smart-tables.ru`, **37 турниров сборных**, **~11 599 матчей**, 11 stat-метрик × 3 периода, prematch 1X2 из карточки, stat-odds только для upcoming/live.

Референс архитектуры — NHL (`conf/source/nhl.yaml`, `sports_forecast/data/providers/nhl/`, done R17/R19/R20). Паттерн `SourceProvider` (R14) уже есть; `conf/sport/football.yaml` — заглушка (R29).

**Phase 1 (этот epic):** ingest → `source.csv` → DVC `clean` → валидный `interim` для будущего обучения.
**Целевые рынки обучения (Phase 2, заложить в sport/tournament config и docs уже в R42):**
- **winner** — 1X2 (home / draw / away);
- **total** — линии **1.5, 2.5, 3.5, 4.5** (`total_over` / `total_under` на каждой линии).

Таргеты тоталов выводятся из `home_points + away_points` (FT); дополнительных API-запросов для backfill не требуется.

**Кэфы (odds):** полнота исторических prematch odds **не блокер R42**. Smart Tables отдаёт 1X2 в карточке (best-effort); **историческое обогащение winner + total** (1.5/2.5/3.5/4.5) — **отдельный источник / отдельный epic** (по аналогии R20/R21 для NHL). Incremental stat-odds ST (R42.15) — опционально для ближайших матчей, не для backfill истории.

**Phase 2+ (вне R42):** features, train/sweep (winner + total×4 линии), **historical odds merge**, materialize, prod Airflow/Telegram, lineups.

## Assumptions (зафиксировано для worker)

| # | Решение |
|---|---------|
| A1 | **Sport slug** = `football` (`conf/sport/football.yaml`) |
| A2 | **Data dir** = `data/source/football_nationals/` (ingest-slug); provider config `conf/source/smart_tables.yaml` |
| A3 | **Provider type** = `smart_tables_api` (абстракция под будущую миграцию на API-Football) |
| A4 | **Scope датасета** = все **37** турниров с `for_national_teams=1` (~11.6k матчей), **не** клубные лиги |
| A5 | **Tournament slug** = `football_nationals` — **один** турнир на весь пул сборных; `competition_code` / `match_importance` — колонки для фильтрации при обучении, **без** split на 37 YAML в Phase 1 |
| A6 | **Рынки обучения** = `winner` (1X2: home / draw / away) **и** `total` на линиях **1.5, 2.5, 3.5, 4.5** (`total_over` / `total_under`); см. `allowed_market_specs` в R42.4 |
| A7 | **Odds в R42 (не блокер):** карточка ST — `odd_home`, `odd_draw`, `odd_away` (**best-effort**, nullable); **исторические кэфы** (winner + total 1.5/2.5/3.5/4.5) — **отдельный источник**, отдельный epic после R42.13 |
| A8 | **stat-odds ST** = опциональный incremental-слой (upcoming/live); **не** цель backfill истории |
| A9 | **Составы / SSR** — вне Phase 1 |
| A10 | **Debug subset** = опциональный фильтр `competition_codes: [WC]` или `max_matches` в source-конфиге для быстрых прогонов |
| A11 | **Rate limit** = 1 req/s + exponential backoff; raw JSON кэш на диск |
| A12 | **Primary key** ingest = `match_id`; `match_center_id` — для incremental stat-odds |
| A13 | **Total target** = `(home_points + away_points)` vs `market_spec.line`; линии фиксированы: `[1.5, 2.5, 3.5, 4.5]` (как `allowed_market_specs.total.lines` в `cyberhockey.yaml`) |
| A14 | **Historical odds enrichment** = вне scope R42; merge по `match_id` / datetime+teams после выбора provider (API-Football, Odds API, Pinnacle и т.д.) |

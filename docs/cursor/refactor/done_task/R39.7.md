# R39.7 — Observability digest + опциональный dedup Telegram при retry

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-05-14
> **Приоритет:** 🔴 High (в составе эпика R39)
> **Сложность:** Low

---

## Решение

Добавлены структурированные INFO-логи в `post_refresh_digest`: после обогащения live odds — турнир/рынок/окно часов, число предиктов, компактная сводка по значениям `live_odds_status`; перед отправкой в Telegram — флаги live Pinnacle и предупреждения по odds, длина текста; после успешной отправки — расширенная строка с теми же метриками и `odds_warning`. В env для отключения digest к списку истинных значений `SF_TELEGRAM_DIGEST_ENABLE` добавлено **`off`** (паритет с типичными boolean-алиасами). Опционально: `SF_TELEGRAM_DIGEST_DEDUP` + переменные `AIRFLOW_CTX_DAG_RUN_ID` / `AIRFLOW_CTX_TASK_ID` — файл-маркер под `<project_root>/.cache/digest_telegram_sent/` пропускает повторную `sendMessage` при ретрае после успеха. В `dag_nhl_morning_refresh.py` добавлены комментарии к `default_args["retries"]` и задаче digest; в `nhl_local_operations.rst` — `off`, dedup и ссылка на docstring модуля. Тесты: `off` без обращения к БД; сценарий с существующим маркером без вызова `telegram_send_message`.

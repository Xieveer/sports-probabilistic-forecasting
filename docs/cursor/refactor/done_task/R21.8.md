## Исходная задача

Из эпика `done_task/R21.md`:

- Unit: V1→V2 миграция store (`migrate_v1_to_v2`, auto-detect, roundtrip)
- Unit: `_totals_line_and_prices` — extraction of point field
- Unit: multi-bookmaker `extract_bookmaker_row_from_event` (Pinnacle 2-way, 1xBet 3-way)
- Unit: `discover_snapshots_for_day` — probe schedule, fallback, minutes_before
- Integration: multi-bookmaker backfill → store V2 → merge source.csv
- Обновить существующие тесты (`test_odds_store.py`, `test_odds_enrichment.py`) для V2 schema

---

## Решение

Написан полный тестовый контур для V2 odds pipeline: 89 тестов в 7 файлах, все проходят, ruff clean.

### Подход

- Все продуктовые модули тестируются через публичный API; внутренние функции (`_totals_line_and_prices`, `_snapshot_discovery_params`) тестируются явно только там, где скрытая логика нетривиальна (point extraction, config fallback).
- Мок-клиенты API реализованы как inline-классы внутри тестов — позволяет точно контролировать ветки probe-алгоритма без fixtures.
- Integration-тест (`test_odds_pipeline_v2_integration.py`) воспроизводит полный pipeline: `events_to_odds_frame` (как в backfill) → `save_odds_store` → `load_odds_store` → `merge_odds_into_source_csv`.
- Config-тест (`test_odds_config.py`) проверяет YAML-контракт (bookmaker_profiles, snapshot_discovery, nhl.yaml) против реального файла конфигурации.

## Проблема

После полного backfill `football_nationals` (R42) аудит выявил **два критических блокера** до `dvc repro clean`:

1. **`match_is_end` bug:** все 11 427 строк в `source.csv` имеют `match_is_end=0`. Smart Tables API отдаёт русский статус `Матч окончен` (и `matches.status.is-walkover` для ~20 матчей). Assembler в `bronze_to_row` проверяет только `finished`/`ended`/`ft` (строчные EN). В `clean._derive_status` такие строки с заполненным счётом классифицируются как **live** и отфильтровываются → `data/interim/football_nationals/` отсутствует.

2. **Пробел `datetime`:** 2 727 строк (23.9%) с пустым `datetime` в CSV, при этом `begin_at` есть в bronze `raw/{match_id}/card.json`. Вероятная причина — resume + `csv_flush_every`: при flush в CSV попали частичные строки из `prev_rows` до обогащения; checkpoint пропустил повторную обработку. `football.yaml` задаёт `drop_na_columns: [id, datetime]` — эти строки будут потеряны в clean.

**Цель:** исправить assembler + пересобрать `source.csv` **из bronze-кэша** (без ~26 ч повторного API backfill), прогнать `dvc repro clean`, получить валидный interim (~11.4k finished rows).

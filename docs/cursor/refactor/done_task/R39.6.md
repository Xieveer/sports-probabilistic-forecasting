# R39.6 — Локальный стек: секреты digest в Airflow Compose + runbook

> **Статус:** ✅ Выполнено
> **Выполнено:** 2026-05-14
> **Приоритет:** 🔴 High (в составе эпика R39)
> **Сложность:** Low

---

## Решение

В якоре `x-airflow-common` файла `airflow/docker-compose.airflow.yml` в блок `environment` добавлена подстановка из хостового `.env`: `ODDS_API_KEY`, `BOT_TOKEN`, `BOT_ALLOWED_USER_IDS` (пустые значения по умолчанию через `${VAR:-}`), чтобы при `make airflow-up` процессы Airflow с LocalExecutor имели тот же контракт секретов, что шаг `post_refresh_digest`. В `docs/source/nhl_local_operations.rst` добавлен пошаговый подраздел «Локальный триггер `nhl_morning_refresh` и digest (R39.6)» и обновлена таблица env относительно compose; в `.env.example` — блок R39.6 с пояснением проброса. Проверка: `docker compose -f docker-compose.yml -f airflow/docker-compose.airflow.yml config --quiet` завершается с кодом 0.

## Проблема (из эпика R39)

Нужна parity локального docker-compose с prod: воркеры Airflow должны видеть ключи Odds и Telegram для digest так же, как при деплое, плюс явные шаги в runbook «поднять стек → триггернуть `nhl_morning_refresh` → получить digest».

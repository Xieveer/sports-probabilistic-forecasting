# R26. Единый контракт odds для беттинг-метрик в `train` (NHL + масштабирование)

> **Статус:** ✅ Выполнено
> **Приоритет:** 🟡 Medium
> **Сложность:** High
> **Выполнено:** 2026-05-03

---

## Проблема

Для **киберхоккея (UEL)** и **настольного тенниса (LP)** беттинг-метрики в `SingleExperimentRunner` уже считаются на **test**: коэффициенты попадают в `odds_raw` (строка Python-dict), маппинг ключей задаётся в `conf/bookmaker/fonbet.yaml`, извлечение — `extract_odds_from_raw` → `BettingSimulator`.

Для **NHL** линии приходят из **The Odds API** и после `merge_odds_into_source_dataframe` лежат в **wide-колонках** в `source.csv`. В `conf/tournament/nhl.yaml` эти поля **не проходили** в `data_clean.select_columns` → в **processed `train_long`** не было ни `odds_raw`, ни числовых closing-колонок → `_compute_business_metrics` фактически **не видел** коэффициентов.

---

## Решение

Выбран путь «как UEL/LP» — на этапе `clean` из merge wide-колонок (Pinnacle close V3/V1) собирается строковый Python-dict в колонке `odds_raw` (та же сигнатура, что у Fonbet); тренер вызывает единый entrypoint `extract_betting_odds`, который ветвится по `bookmaker.odds_transport.mode` (по умолчанию — `extract_odds_from_raw`, т.е. через dict).

**Ключевые изменения:**

1. **`conf/bookmaker/the_odds_api.yaml`** — добавлены `market_keys`, `side_keys`, секция `synthetic_odds_raw` (кандидаты колонок h2h + totals по приоритету V3→V1), опциональный `odds_transport` для прямого wide-режима.

2. **`conf/tournament/nhl.yaml` / `nhl_train.yaml`** — `build_synthetic_odds_raw: true`, `synthetic_odds_raw_bookmaker: the_odds_api`, `odds_raw` добавлен в `select_columns`; в nhl_train — комментарий о R26 Hydra defaults.

3. **`sports_forecast/data/clean.py`** — шаг 5.5: вызов `try_attach_synthetic_odds_raw_column` до `derived_columns`; загружает профиль букмекера через `load_bookmaker_config`.

4. **`sports_forecast/betting/odds.py`** — `winner_withOT` обработан наравне с `winner` в `get_odds_column_long_format`, `_resolve_raw_key`, `extract_odds_from_raw`; добавлены `build_synthetic_odds_raw_series`, `try_attach_synthetic_odds_raw_column`, `_extract_odds_wide_transport`, `extract_betting_odds` (единая точка входа).

5. **`sports_forecast/config/validation.py`** — `apply_tournament_default_bookmaker`: при `tournament.name` начинается с `nhl` и `bookmaker.name == fonbet` — подменяет узел на `the_odds_api`.

6. **`sports_forecast/train.py` + `SingleExperimentRunner`** — вызов `apply_tournament_default_bookmaker` при старте; `extract_odds_from_raw` → `extract_betting_odds`; логирование `bookmaker.name`, доли валидных odds, явное предупреждение при нулевом покрытии.

7. **Тесты** — `tests/test_odds.py` (+`TestGetOddsColumnLongFormat::winner_withOT`, `TestExtractOddsWinnerWithOT`, `TestSyntheticOddsRawBuild`, `TestExtractBettingOddsWideTransport`); `tests/test_odds_config.py`; `tests/test_config_validation.py` — 67 тестов, все проходят.

8. **Документация** — `HOW_TO_ADD_NEW_TOURNAMENT.md`: раздел «Odds для обучения и BettingSimulator (dict vs merge wide)» с таблицей источников.

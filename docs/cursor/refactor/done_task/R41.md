## Проблема

После R37/R38/R39 операционный контур «данные → витрина → Telegram» стал воспроизводимым для NHL (`nhl_morning_refresh`, CLI `post_refresh_digest`, паритет обогащения с HTTP-слоем). При этом восприятие кода как **неуниверсального** справедливо: одновременно существуют NHL-имёнованные DAG/скрипты/переменные Airflow; админ-команда бота `/refresh` триггерит **`data_refresh` (полный source→features→materialize)** и смешивается с пользовательским сценарием «покажи актуальные котировки/edge».

Целевая архитектурная картина (согласована с `docs/cursor/context/service_orchestration_architecture.md`):

1. **Тяжёлый путь (scheduled / по необходимости):** обновление сырых данных, сборка фичей, материализация витрины, опционально **одно** операционное сообщение (digest уже не пересчитывает фичи — только БД + The Odds API).
2. **Лёгкий путь для пользователя:** только чтение витрины + **повторное получение живых коэффициентов** и пересчёт edge/decision при тех же сохранённых вероятностях; **без** триггера ingest/clean/features. Реализуется через публичный API (`live_pinnacle`) и/или явное действие в боте, **не** через Airflow DAG.
3. **Multi-tournament:** списки турниров/рынков и расписание — через конфигурацию и Airflow Variables (`SF_*`), а не через копирование DAG «на каждую лигу».
4. **Один связный конфиг на турнир:** train/inference/data уже сфокусированы в `conf/tournament/<slug>.yaml` (R38); остался deprecated `nhl_train.yaml` и риски расхождений документации/команд со «старой» связкой турниров.

Опционально: **минимизация пересчёта фичей**, когда исходные артефакты не менялись (operational fingerprint / checkpoint; DVC в prod не обязателен на каждый триггер, но для dev/CI остаётся источником воспроизводимости). Ограничение EWM из архитектурного документа сохраняется: «пропуск features» допустим только при строгом контракте на идентичность входов и осознанном риске при правках истории.

## Решение

Зафиксирован контракт **light vs heavy** в архитектурном документе и NHL runbook; пользовательский сценарий **`/edge`** и callback `edge:` в боте вызывают только **GET** `/predict/upcoming/{tournament}` с `live_pinnacle` (тот же контракт, что у digest/API), без Airflow. Админский **`/refresh`** явно помечен как тяжёлый путь.

Для Airflow вынесены повторяющиеся bash/Jinja-фрагменты в `sports_forecast/orchestration/airflow_post_refresh_digest_bash.py` и `airflow/dags/sf_scheduled_refresh_ops.py`; `dag_nhl_morning_refresh` стал тонкой обёрткой.

Удалён **`conf/tournament/nhl_train.yaml`**; документация (`HOW_TO_ADD_NEW_TOURNAMENT.md`, `nhl_single_tournament_slug.md`, `repo-index.md`) согласована с каноническим `tournament=nhl`.

Регрессии: `tests/test_bot_light_refresh_path.py`; интеграционные тесты оркестрации обновлены под новые модули.

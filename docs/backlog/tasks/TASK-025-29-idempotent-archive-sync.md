# TASK-025-29 — Сделать повтор archive-sync идемпотентным

> **Статус:** done — решение о закрытии EPIC-025 от 2026-10-03
> **Владелец:** Developer
> **Эпик:** [EPIC-025](../EPIC-025-bot-schedule-readiness.md)

## Наблюдаемый дефект

Data Cycle v1.2.10 записал прогнозы, но завершился ошибкой на `archive_sync`:
Object Storage вернул `ReadTimeoutError`. Runner вызывает отдельный archive-sync
для каждого найденного immutable manifest, включая ранее синхронизированные
архивы. Реализация повторно загружала и затем целиком сверяла скачиванием все
файлы такого архива при каждом Data Cycle. Это создавало лишний сетевой объём и
делало завершение ежедневного цикла зависимым от повторной передачи старых
архивов.

## Критерии исправления

- [x] Регрессионный тест воспроизводит повторный вызов с durable `verified`
  состоянием и доказывает отсутствие сетевых операций.
- [x] Пропуск допускается только после локальной проверки архива и при точном
  совпадении `artifact_id`, нормализованного Object Storage prefix и статуса
  `verified`; отсутствующее, повреждённое или неуспешное состояние запускает
  обычную upload и remote verification.
- [x] Старые production state записи без prefix мигрируются только для двух
  штатных prefix, если `ListBucket` точно подтверждает полный ожидаемый набор
  ключей без дополнительных объектов, а скачанный remote manifest побайтно
  совпадает с локальным. Для любого другого prefix выполняется полная upload и
  remote verification.
- [x] S3 client использует конечные connect/read timeout и стандартные повторы
  для временных ошибок.
- [x] При новой ошибке сохраняется существующая семантика: staging остаётся,
  durable state становится `failed`, исключение завершает sync ненулевым кодом.
- [x] Адресные тесты и lint проходят под ограничениями ресурсов; полный pytest и
  production не запускались/не менялись.

## Граница

Не меняются формат архива, ключи Object Storage, право доступа к удалённым
объектам, shell runner, API и production данные. Durable `verified` state
предполагает неизменяемость content-addressed remote artifact внутри prefix
после успешной побайтовой проверки.

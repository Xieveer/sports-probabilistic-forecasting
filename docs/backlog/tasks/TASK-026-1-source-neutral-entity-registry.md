## Результат и границы

Внутренний сервис хранит проектный ID и редактируемое имя сущности отдельно от
её внешних ID и названий. Запись и разрешение выполняются локально без сетевого
запроса; серверное чтение будет отдельной TASK. Схема и правила не зависят
от NHL; NHL и второй турнир используются как проверяемые примеры. Рабочий календарный
ingest, прогнозы и текущий YAML-мэппинг в этой TASK не переключаются.

## Критерии приёмки

- [x] Турнир и команда имеют проектные ID и имена; изменение имени сохраняет ID.
- [x] Подтверждённые `COL` и `Colorado Avalanche` разрешаются в одну команду
      с сохранением источника каждого обозначения.
- [x] Неизвестная и конфликтная связь не получает подтверждённый ID по
      похожести строки и доступна для следующего этапа проверки; новое
      designation по умолчанию `pending`, даже при наличии предложенного entity.
- [x] Разрешение конфликта применяется к интервалу пересечения, сохраняет
      base designation за его пределами; отклонение закрывает только связанные
      overlays, а отложенное решение оставляет конфликт открытым. Owner может
      выбрать подинтервал; невыбранные остатки остаются открытыми.
- [x] Повторный импорт проверенного NHL-мэппинга идемпотентен и не
      перезаписывает решение владельца.
- [x] Схема допускает идентичность игрока и отдельную датированную связь с
      командой без реализации player-прогнозов.
- [x] Контрактный пример второго турнира проходит теми же операциями и без
      ветвления Python-кода по его названию.
- [x] Разрешение и регистрация обнаруженных связей локально работают без
      серверного API.

## План реализации

1. Написаны поведенческие тесты UUID, переименования, scope, решений владельца,
   конфликтов, временных membership и контрольного турнира; red подтверждён
   ошибкой импорта ещё не существовавшего пакета.
2. Добавлены отдельная явно инициализируемая SQLite schema и source-neutral API.
3. Добавлен идемпотентный доверенный NHL YAML seed; проверены календарь и odds
   regressions без переключения текущего matcher.
4. Закрыты findings Reviewer: стабильная идентичность seed, атомарный импорт,
  интервальная дедупликация и разрешение, optimistic revision решений и
  нормализация UTC. Все base designation сохраняют заданные state и entity ID;
  open overlay блокирует разрешение только на пересечении. Reject помечает
  связанные overlays как dismissed, defer сохраняет open; повторная проверка
  покрывает три конкурирующие привязки и частичное разрешение overlay с
  сохранением open остатка. NHL importer переиспользует entity по любому уже
  известному NHL API source ID, поэтому добавление alias не меняет ID. Reject
  ранее разрешённого designation инвалидирует overlay, сохраняет выбранный ID и
  предыдущее решение в audit history и возвращает resolver к оставшимся base.

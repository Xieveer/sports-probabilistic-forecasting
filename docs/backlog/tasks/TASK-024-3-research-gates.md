## Результат и границы

Research-контракт может задать долю положительных bootstrap-прогонов, coverage ставок
и требование превосходства симулированного profit над baseline и текущей моделью.
ML-пороги можно определить после разведки. Старые сохранённые run остаются читаемыми.

## Критерии приёмки

- [x] Отсутствующая обязательная метрика даёт INVALID, проваленный порог — FAIL.
- [x] Кандидат не получает PASS без требуемого profit превосходства на сопоставимом тесте.
- [x] Старые контракты и run не ломаются из-за новых необязательных полей.

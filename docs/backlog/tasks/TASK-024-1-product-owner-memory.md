## Результат и границы

Компактное состояние хранится в управляющем блоке существующего EPIC, а для одношагового
bug fix — в TASK. Оно связывает цель, критерии, ветку, этап, решения, артефакты,
следующую роль и Research-сводку. После нового запуска по явному ID восстанавливаются
две независимые инициативы. Секреты, история чата и полные внешние ответы не сохраняются.

## Критерии приёмки

- [x] Две инициативы с разными ветками не смешивают состояние и восстанавливаются по ID.
- [x] Значимый переход обновляет этап и следующий шаг без потери исходной цели.
- [x] Шаблоны EPIC/TASK требуют блок памяти; неверная ветка или неоднозначный контекст
  запускают сверку с Git, а не тихое переписывание памяти.

## План реализации

1. Падающий тест обязательного блока памяти в шаблонах.
2. Управляющий блок в EPIC/TASK и его валидация в `make ai-validate`.
3. Сценарий восстановления двух инициатив и инструкция Product Owner.

## Затрагиваемые области и зависимости

Существующие шаблоны EPIC/TASK, валидатор AI-слоя и инструкция Product Owner. Новый
runtime, CLI или отдельный обязательный state-файл не создаются.

## Проверка

Фокусные тесты валидатора, `make ai-validate` и read-only сценарий восстановления.

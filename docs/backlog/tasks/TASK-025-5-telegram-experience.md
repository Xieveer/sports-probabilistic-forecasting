# TASK-025-5 — Календарь и управление циклом в Telegram

> **Владелец:** Developer
> **Эпик:** [EPIC-025](../EPIC-025-bot-schedule-readiness.md)
> **Требование:** [REQ-025](../../product/requirements/REQ-025-bot-schedule-readiness.md)

## Результат и границы

Telegram использует календарь событий и readiness API для публичного просмотра,
а администратору показывает настройки, состояние и историю Data Cycle через
control API. Публичный бот остаётся NHL-only в `1.2.0`; футбольный сценарий
проверяется на уровне общего API-контракта.

## Критерии приёмки

- [ ] «Сегодня», «Завтра», `3`, `7`, `14`, `30` показывают известные будущие
  события в букмекерских сутках 08:00–08:00 МСК, включая события без прогноза
  или коэффициентов. Пустое подтверждённое расписание отличается от неполного
  покрытия и ошибки обновления.
- [ ] У каждого события видны время, участники, состояние календаря, прогноза,
  коэффициентов и понятный итог; перенос и отмена не теряют идентичность.
- [ ] Администратор видит enabled, время/зону/интервал, следующий и прошлый
  запуск, текущий этап, историю и числовое покрытие; может изменить допустимые
  настройки и запросить новый цикл. Повтор callback идемпотентен, активный
  `run_id` показан без запуска дубля.
- [ ] После ручного запуска бот сообщает принятие с `run_id`, затем итог;
  после планового отправляет один компактный итог. `partial_success` и `failed`
  обозначены явно; повторная доставка не создаёт дублирующих сообщений.
- [ ] Неадминистратор не видит административные действия и не может вызвать
  control API через подмену callback. Существующие команды прогнозов остаются
  работоспособными по своему контракту.
- [ ] Кодовый сценарий `Telegram handler → API → calendar → readiness` и
  сценарий управления проходят локально и в CI без браузера, production token
  и production-запросов.

## План реализации

1. Red: тесты границ 08:00, всех горизонтов, пустого/ошибочного покрытия,
   события без прогноза, auth, дубля callback и результата run.
2. Green: публичные и административные handlers, форматирование, клиент
   ограниченного control API, доставка итогов из durable outbox.
3. Refactor: единые подписи статусов, помощь и runbook тестирования бота.

## Зависимости и проверка

- Зависит от TASK-025-1…4. Доставка уведомлений использует результаты и
  outbox Data Cycle, без прямого управления службами из процесса бота.
- Целевые unit/ASGI/bot integration tests с fake clock и fake Telegram
  transport; регрессия старых команд; lint.

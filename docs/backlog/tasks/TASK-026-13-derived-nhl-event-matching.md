# TASK-026-13 — Производное сопоставление NHL событий и коэффициентов

> **Статус:** done
> **Эпик:** [EPIC-026](../EPIC-026-entity-registry.md)
> **Требование:** [REQ-026](../../product/requirements/REQ-026-entity-registry.md)
> **Решение:** [ADR-035](../../architecture/adr/ADR-035-registry-dictionaries-and-derived-event-matching.md)

## Результат

Связь NHL события выводится по подтверждённым обозначениям турнира и команд,
направлению home/away и kickoff в UTC с включительным допуском ±15 минут.
Результат принимается только при взаимной уникальности пары во всём переданном
окне календаря и события источника. Неоднозначность и неизвестные обозначения
не дают коэффициент; неизвестные обозначения остаются в потоке owner review.
Регулярные неизвестные ID события не создают review-кандидаты.

Live Pinnacle, future batch и NHL-проекция OddsStore используют одну проверку
производного соответствия. Live и future принимают Pinnacle `h2h` только после
разрешения проектного рынка `winner_withOT` и соответствующего правила game,
overtime и shootout, без ничьей, с точным набором home/away. Исходы команд сверяются
с подтверждёнными обозначениями команд. Неизвестный market alias передаётся владельцу
как scoped candidate в future batch и OddsStore projection.

Future batch запрашивает Odds API с запасом ±15 минут от целевого окна и загружает
соседние календарные события для mutual-uniqueness. События за пределами целевого
горизонта участвуют в проверке неоднозначности, но не материализуются. Повторные
одинаковые строки одного provider event ID сворачиваются; конфликтующие валидные
копии отклоняются, а структурно непригодная копия не блокирует единственную валидную.

## Критерии

1. Шесть подтверждённых NHL/Pinnacle примеров с разницей +10 минут принимаются;
   +15 минут включается, +16 минут отклоняется.
2. Дубликаты, конкурирующие календарные/провайдерские события, обратный порядок
   команд и неизвестные alias не дают ложного соответствия.
3. Live, future и NHL OddsStore projection не используют owner-maintained links
   событий; provider event ID сохраняется там, где он присутствует в источнике.
4. Дополнительные события по краям окна участвуют в uniqueness, но остаются вне
   целевого набора observations.
5. Правила рынка и состав исходов сверяются с установленным registry snapshot.

## Границы

- Срез касается NHL; перенос такого контракта на другие турниры требует
  подтверждённых aliases и market rules.
- Historical OddsStore rows не содержат provider event ID и исходные provider
  labels. Эта проекция не изобретает provenance; идентификатор остаётся пустым.
- Для не-NHL источников сохранён существующий путь проекции до их отдельной
  миграции.
- Это завершение TASK не заменяет независимый review и интеграционные/release gates
  EPIC-026.

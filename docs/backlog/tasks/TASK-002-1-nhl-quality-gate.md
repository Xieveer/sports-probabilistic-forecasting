## Результат и границы

Добавить турнир-нейтральный quality gate, который перед пользовательским digest
сравнивает результат source refresh с локальным `source.csv`. Gate подтверждает:
все матчи источника в заданном профилем окне есть ровно по одному разу, а все
завершённые матчи от последней локально сохранённой завершённой игры до текущего
refresh имеют итог и обязательные поля. Не изменяются модель, материализация,
источник коэффициентов и пользовательский формат Telegram. NHL-профиль задаёт
48 часов, поля NHL и правило завершённого матча.

## Критерии приёмки

- [x] Неполное либо дублированное расписание в окне профиля завершает gate ошибкой.
- [x] Пропущенный завершённый матч, пустой итог или повреждённое обязательное
  поле в проверяемом диапазоне завершает gate ошибкой.
- [x] Полный корректный набор проходит gate; диагностическое сообщение не
  содержит полных внешних ответов или секретов.
- [ ] Gate вызывается в heavy DAG профиля до initial digest; при ошибке digest не запускается.

## План реализации

1. Написать падающие unit-тесты для полного набора, пропуска, дубля и
   незавершённого результата; зафиксировать формат `ValidationResult`/ошибки.
2. Реализовать изолированную проверку по нормализованным строкам source, снимку
   расписания и правилам профиля, без изменения общих Pandera-схем.
3. Подключить её отдельной task DAG после текущего heavy refresh и до digest;
   добавить source-level DAG test.
4. Запустить целевые тесты и зафиксировать результат в отчёте TASK.

# TASK-026-10 — Строгий reader и полный production feedback цикл

> **Статус:** blocked — ожидание релизного окна
> **Эпик:** [EPIC-026](../EPIC-026-entity-registry.md)
> **Требование:** [REQ-026 #10](../../product/requirements/REQ-026-entity-registry.md)

## Результат

Сервер разрешает события и команды только по установленному проверенному
snapshot, отправляет неизвестный кандидат локально, получает решение владельца
через новую публикацию и сохраняет прежнюю рабочую версию при ошибке.

## Локальная подготовка

После [TASK-026-9](TASK-026-9-legacy-yaml-cutover.md) подготовить preflight
полноты NHL событий ближайшего горизонта, тесты отказа и обратимый план
переключения. Локально проверить применение непустого кандидата и повтор.
Владелец разрешил первоначальное создание однозначных project events из
официального NHL API при подтверждённых командах и точном UTC времени;
конфликты остаются в очереди, букмекерские event IDs отдельно проверяются.

Снимок v1.3.1 содержит 33 команды, 1 турнир и 100 командных обозначений
(33 NHL ID, 33 NHL web name и 34 Odds API name), но
не содержит событий. Он подтверждает первичный перенос команд, а не покрытие
строгого event matcher. Перед переключением требуется новый проверенный
snapshot с подтверждёнными событиями, relations и нужными bookmaker event IDs
на контрольном горизонте. Отсутствующие связи остаются кандидатами, а не
получают fallback по имени.

## Релизный gate

В явно согласованное релизное окно Operations Agent защищает копию master,
проверяет реальный NHL горизонт и включает strict reader только при достаточном
покрытии. Проверяет получение непустого кандидата, локальное решение владельца,
новую публикацию/sync, доступность прогноза и возврат на прежнюю версию. До
этого gate задача остаётся `blocked`, даже при зелёных локальных тестах.

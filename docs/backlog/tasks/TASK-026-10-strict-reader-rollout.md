# TASK-026-10 — Строгий reader и полный production feedback цикл

> **Статус:** blocked — непустой owner candidate cycle ожидает подключения нового турнира
> **Эпик:** [EPIC-026](../EPIC-026-entity-registry.md)
> **Требование:** [REQ-026 #10](../../product/requirements/REQ-026-entity-registry.md)

## Результат

Сервер использует опубликованные словари турниров, команд, рынков и исходов в
строгом режиме. Матч сопоставляется по подтверждённым командам и времени начала
в пределах 15 минут; непонятное обозначение попадает в локальную очередь,
после решения владельца новая публикация применяется сервером. Предыдущий
проверенный snapshot доступен для отката.

## Локальная подготовка

Исторический snapshot v1.3.1 с 33 командами не покрывал событий по прежнему
контракту. [ADR-035](../../architecture/adr/ADR-035-registry-dictionaries-and-derived-event-matching.md)
заменил обязательные owner event links словарями и вычисляемым сопоставлением.
В v1.3.6 строгий reader на NHL прошёл цикл с проверенным snapshot v2 sequence 3;
актуальный NHL outbox пуст. Legacy YAML и старый код остаются для отдельного
удаления по [TASK-026-9](TASK-026-9-legacy-yaml-cutover.md).

## Релизный gate

Strict reader уже включён в production. Владелец 2026-10-12 перенёс проверку
непустого кандидата, локального решения, новой публикации/sync/ack и возврата
на предыдущий snapshot на подключение нового турнира: у текущего NHL все команды
известны. Этот сценарий остаётся открытым и не считается пройденным по нулевой
очереди; рабочий strict NHL и zero-work feedback проверяются отдельно в
[EPIC-039](../EPIC-039-v1-3-7-daily-cycle.md).

# TASK-040-4 — Проверить границы конфигурации и инструментов

> **Статус:** done
> **Инициатива:** [EPIC-040](../EPIC-040-club-football-platform-e2e.md)
> **Требование:** [REQ-040](../../product/requirements/REQ-040-club-football-platform-e2e.md)
> **Решение:** [ADR-041](../../architecture/adr/ADR-041-local-data-stage-tournament-selection.md)

## Цель

Проверить на клубном E2E, какая конфигурация действительно управляет запуском,
какие инструменты нужны для ежедневного результата и где остаются дублирующие
списки. Убирать путь только после проверки текущего потребителя и регрессий.

## Проверенные наблюдения

| Компонент | Фактическая роль | Вывод для этой инициативы |
| --- | --- | --- |
| Hydra | Композиция турнира, рынка, стратегии и обучения; оба кандидата используют один `winner_1x2` и разные `model_strategy` | Иерархические дифы работают для модели, но сами по себе не делают все пути запуска единым каталогом. Сохранить. |
| DVC | Локальный граф данных до processed; features выбирает все готовые interim-турниры с Hydra-конфигом | Ручной список из `dvc.yaml` удалён. Клубный пул обнаруживается вместе с девятью существующими interim-турнирами. DVC не используется в production serving. |
| Airflow | `portfolio_refresh` строит задачи из deployment profiles; legacy `data_refresh` сохраняет ручной список | У legacy DAG отключено расписание, поэтому второй общий плановый путь не конкурирует с `portfolio_refresh`. Production Compose использует systemd data-cycle и Worker, без Airflow. |
| MLflow | Локальные runs и candidate artifacts, модельный promoter; Worker использует immutable bundle без MLflow | Полезен для сравнения экспериментов, не нужен в daily serving. Два smoke-run записаны с разной identity. |
| Pandera | Исполняемые raw/interim/processed схемы и quality gates | Оставить: входные спортивные данные дали реальные исключения UCL/UEL. Проверки семантики основного времени выполняются отдельно до обучения. |
| Prometheus/Grafana | `/metrics` существует в API, локальный Compose содержит scraper/dashboard | В `docker-compose.prod.yml` нет Prometheus/Grafana; `update_prometheus_metrics` не имеет runtime-вызовов. Нельзя считать ML-графики подтверждённым production monitoring. |

## Нерешённые архитектурные долги

1. `football_top_leagues` представлен одним модельным пулом, но физические
   данные девяти соревнований пока не образуют отдельные управляемые source
   units. Это приемлемо для текущего общего обучения; стоимость добавления
   другого спорта надо проверять отдельным вертикальным срезом.
2. Реальный upcoming Smart Tables проходит локальный E2E до API и
   тестовой выдачи в Telegram. Регулярный production цикл для клубного пула
   не включён по решению о границе инициативы; своевременность расписания
   этим тестом не доказана.
3. Ручной legacy DAG остаётся в репозитории для диагностики. Его внешние
   пользователи не подтверждены; полное удаление потребует отдельной проверки.

## Решение на текущем gate

Сохранить Hydra для композиции, Pandera для quality gates, DVC для локального
графа и MLflow для экспериментов. Клубный пул не включать в production
scheduler без отдельного решения. Исправления состава DVC и legacy-расписания
зафиксированы в ADR-041; наличие локальных Prometheus/Grafana не означает
действующий production monitoring.

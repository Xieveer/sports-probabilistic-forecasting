# REQ-001 — Переход проекта на Python 3.12

> **Статус:** confirmed
> **Владелец продукта:** владелец репозитория
> **Создано:** 2026-08-07

## Результат и ценность

Проект, его локальное окружение, CI и Docker-образы используют Python 3.12 как единственную
поддерживаемую версию. Это устраняет расхождение между локальным Python 3.10 и CI/образами,
включая невозможность запуска AI-валидации из-за отсутствия `tomllib` в Python 3.10.

## Scope

- Зафиксировать поддержку Python 3.12 в `pyproject.toml`, `uv.lock` и `.python-version`.
- Перевести CI и прикладной/Airflow Docker runtime на Python 3.12.
- Синхронизировать пользовательскую и инженерную документацию.

## Non-scope

- Обновление версий прикладных зависимостей вне необходимости для разрешения lockfile.
- Изменение кода предметной области, deployment и исторических Cursor-артефактов.

## Сценарии

1. Разработчик выполняет `uv sync`, и окружение создаётся на Python 3.12.
2. CI устанавливает и тестирует единственную поддерживаемую версию Python 3.12.
3. API/worker и Airflow запускаются на образах Python 3.12.

## Критерии приёмки

- [x] `requires-python` ограничен Python 3.12.
- [x] В CI и обоих Dockerfile отсутствуют runtime-ссылки на Python 3.10/3.11.
- [x] `uv.lock` пересобран без ручного редактирования и совместим с Python 3.12.
- [x] README и актуальная инженерная документация называют Python 3.12.
- [x] Релевантные проверки конфигурации и тесты выполнены либо честно отмечены как недоступные.

## Ограничения, зависимости и риски

- `apache/airflow:2.10.4-python3.12` существует; Airflow 2.10.4 официально поддерживает
  Python 3.12. Источник: [Docker Hub](https://hub.docker.com/layers/apache/airflow/2.10.4-python3.12/images/sha256-94b74c8b65924179b961b8838e9eaff2406d72085c612e0f29b72f886df0677e),
  [release notes Airflow](https://airflow.apache.org/docs/apache-airflow/2.10.4/release_notes.html).
- Локальный `.venv` на Python 3.10 потребуется пересоздать через `uv sync`.

## Предположения и открытые вопросы

- Предположение: production runtime следует закреплённому Dockerfile; отдельные внешние
  окружения будут обновлены при следующем штатном rollout.

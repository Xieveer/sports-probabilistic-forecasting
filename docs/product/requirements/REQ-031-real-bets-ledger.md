# REQ-031 — Журнал фактических ставок

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-10-10
> **Инициатива:** [EPIC-031](../../backlog/EPIC-031-real-bets-ledger.md)

## Результат и ценность

Владелец видит прогноз и рекомендацию с линией Pinnacle в Telegram, но фактически
ставит в Winline. Ему нужна проверяемая история собственных ставок и реального
денежного результата отдельно от модельной симуляции. Фактический коэффициент
Winline может отличаться от показанного в рекомендации.

## Подтверждённые факты сценария

- По одному матчу владелец может поставить несколько раз в течение дня, каждый
  раз на другую сумму и по другому коэффициенту.
- Ставка может быть сделана собственными деньгами или фрибетом.
- По действующему для владельца фрибету Winline при выигрыше выплачивается
  только выигрыш сверх номинала: сам номинал не возвращается.
- При void фрибета Winline не возвращает его номинал: фрибет сгорает.
- Все фактические ставки Winline в первом срезе ведутся в российских рублях.
- Дата и время размещения ставки и дата и время её расчёта фиксируются отдельно.
  Финансовые показатели месяца относятся к дате расчёта ставки в МСК.
- Владелец подтвердил ввод фактической ставки из отдельной карточки прогноза
  в Telegram-боте. Рекомендация не запрещает владельцу поставить на другой
  исход или без рекомендации.
- В момент записи нужны матч, сумма и фактический коэффициент; связь с прогнозом
  и показанной котировкой должна сохранять исходную версию, если она доступна.

## Карточка прогноза и команды бота — требования владельца 2026-10-11

- `/predict` предлагает периоды по тому же правилу, что `/upcoming`: сегодня,
  завтра, 3/7/14/30 букмекерских суток с границей 08:00 МСК. Текущее
  скользящее окно 48 часов не является определением «сегодня».
- Каждый прогноз приходит отдельным сообщением с кнопкой записи ставки.
  Время начала показывается в МСК. Для NHL допустимы сокращения команд;
  при последующей выдаче футбола нужны единые полные проектные названия.
- Две вероятности для `winner_withOT` показываются одной строкой с явным
  названием рынка и порядком `home | away`. Pinnacle и Edge также показываются
  компактными парами в том же порядке. Добавляется EV для обеих сторон:
  `EV = probability × decimal_odds − 1`, если цена и вероятность доступны.
  Отсутствующее значение показывается как отсутствие данных, не как ноль.
- Рекомендация формируется по каждому рынку и исходу: для текущего рынка
  показаны `home win with OT`, `away win with OT` либо `нет рекомендации`.
  Будущая модель по тоталу может добавить собственную рекомендацию без
  перезаписи рекомендации победителя. Отсутствие рекомендации не скрывает
  кнопку ручной записи ставки.
- `/edge` удаляется из доступных команд и обработчиков: для прогноза остаётся
  один путь `/predict` с актуальной линией. `/models` также удаляется.
- В `/predict` сейчас показывается только NHL; турниры без регулярных прогнозов
  не попадают в выбор. Административные описания `/cycle` не должны обещать
  управление только NHL. Выбор доступного цикла берётся из API; сейчас API
  реально поддерживает только NHL, и неподдерживаемый турнир не запускается.

## Подтверждённый scope первого среза

- Вводить каждое фактическое размещение как отдельную запись через доступный
  только владельцу сценарий Telegram-бота, начиная с выбранного прогноза или
  матча. Повторный добор добавляет запись и не меняет предыдущую.
- Для записи фиксировать событие, рынок с правилами расчёта, исход, букмекер,
  время размещения, фактический decimal coefficient, номинал ставки, валюту и
  тип средств: собственные деньги или фрибет. Фактическую цену Winline не
  подменять котировкой Pinnacle.
- Сохранять неизменяемую ссылку на prediction revision и, если доступна,
  исходную котировку рекомендации. Если прогноз не имеет подтверждённой revision
  или котировка не имеет observation ID, показывать это явно; не создавать
  фиктивную связь. Отсутствие revision не запрещает запись фактической ставки.
- До сохранения показывать владельцу подтверждение суммы, коэффициента, исхода,
  типа средств и расчётных правил; повторная доставка Telegram-события не
  создаёт вторую ставку.
- Вручную отмечать расчёт ставки и исправлять ошибку с историей того, кто,
  когда и что изменил. Хранить фактически полученную выплату отдельно от
  расчётной формулы. Для выигравшего фрибета ожидаемая денежная выплата равна
  `номинал × (коэффициент − 1)`; расхождение с фактической выплатой показывать
  явно.
- Показывать список отдельных ставок и сводку за выбранный календарный месяц
  по дате расчёта, с разрезом по букмекеру, рынку и типу средств. До расчёта
  ставка остаётся в отдельном списке открытых; её не относить к финансовому
  результату месяца. Денежный результат и оборот собственных денег не смешивать
  с номиналом фрибетов.

## Денежный отчёт — подтверждён владельцем 2026-10-11

- Для обычной рассчитанной ставки денежный PnL = фактическая денежная выплата
  минус поставленная сумма. При выигрыше ожидаемая выплата — сумма × коэффициент;
  при проигрыше — ноль; при полном возврате — сумма и PnL ноль.
- Для фрибета денежный PnL = фактическая денежная выплата: номинал не списывался
  из собственных денег. При выигрыше ожидаемая выплата — номинал ×
  (коэффициент − 1); при проигрыше и void — ноль. При void номинал фрибета
  сгорает и не считается денежным расходом из собственных средств.
- Показывать раздельно оборот и ROI обычных ставок (`PnL / сумма обычных
  рассчитанных ставок`), номинал и денежную выплату фрибетов, а также общий
  денежный PnL. Общий ROI по смешанным деньгам и фрибетам не вычислять:
  знаменатели у них имеют разный смысл.
- Hit rate считать по рассчитанным win/loss ставкам; void и открытые ставки
  показывать отдельным количеством. Для первого среза предлагать ручной
  settlement каждой записи, с вводом фактической выплаты и историей исправления.

## Non-scope первого среза

- Автоматическое размещение ставок, вход в Winline и синхронизация с его счётом.
- Автоматический расчёт по результату матча без проверки владельцем.
- Признание котировки Pinnacle фактической ценой Winline.
- Cash-out и экспрессы: владелец сейчас не использует их; поддержка экспрессов
  может быть рассмотрена после практической проверки ценности одиночных ставок.
- Частичный расчёт одной ставки: в первом срезе учитываются одиночные ставки
  с полным исходом win/loss/void.
- Изменение исследовательской симуляции EPIC-030 и выпуск production-версии.

## Сценарии и критерии приёмки

1. Владелец выбирает прогноз и записывает ставку собственными деньгами по цене
   Winline. Сохранённая запись содержит фактические условия и исходную revision;
   следующая материализация прогноза их не меняет.
   Если у прогноза нет подтверждённой revision, запись ставки всё равно
   сохраняется с явной пометкой отсутствия ссылки.
2. Владелец делает второй добор того же исхода по другой цене или на другую
   сумму. Список показывает две отдельные записи, а сводка включает обе ровно
   один раз.
3. Владелец записывает фрибет. Номинал акции, фактическая денежная выплата и
   результат по собственным деньгам отображаются раздельно. При выигрыше
   расчётная выплата фрибета не включает его номинал.
4. Владелец рассчитывает ставку как выигрыш, проигрыш или возврат и исправляет
   ошибочный расчёт. История позволяет восстановить прежнее и новое значение.
   При void обычной ставки возвращённый номинал даёт PnL ноль; при void
   фрибета номинал сгорает и денежная выплата равна нулю.
5. За выбранный месяц по дате расчёта сумма строк сходится со сводкой по
   выплатам, PnL, обороту и числу ставок; разрезы по букмекеру, рынку и типу
   средств также сходятся с общим итогом. Ставка, размещённая в прошлом
   месяце и рассчитанная в текущем, относится к текущему. Нерассчитанные
   ставки явно исключены из ROI и hit rate.
6. Пользователь без прав владельца не может создавать, менять или читать журнал
   фактических ставок. Симулированные ставки не попадают в эту сводку.
7. `/predict` для выбранного периода возвращает только прогнозы в том же
   полуоткрытом окне букмекерских суток 08:00–08:00 МСК, что `/upcoming`, и
   отправляет каждый отдельным сообщением. Переход через границу 08:00,
   отсутствие прогнозов и недоступная котировка проверяются отдельно.
8. Карточка показывает время МСК, явно названный рынок, вероятности и
   коэффициенты `home | away`, Edge, EV и рекомендацию по рынку. При двух
   рекомендациях разных рынков они не сливаются в одно неоднозначное решение;
   без рекомендации запись фактической ставки доступна.
9. Меню и справка не предлагают `/edge`, `/models` и турниры без регулярной
   выдачи. `/cycle` показывает доступные API циклы без NHL-хардкода в боте;
   при единственном поддерживаемом цикле явно виден NHL.

## Ограничения, зависимости и риски

- [EPIC-028](../../backlog/EPIC-028-production-model-contract.md) предоставляет
  prediction revision. Текущий публичный ответ API не содержит её ID; для
  связывания из Telegram нужен отдельный защищённый контракт.
- [EPIC-027](../../backlog/EPIC-027-historical-odds.md) хранит локальную историю
  Pinnacle; текущая сервисная `odds_observations` — последняя линия, а не
  неизменяемый журнал. Способ связи с котировкой рекомендации требует решения.
- [EPIC-026](../../backlog/EPIC-026-entity-registry.md) даёт идентичность событий;
  его серверный gate нужен для production-подключения.
- EPIC-029 и EPIC-030 уже слиты в `main` и включены в базу ветки EPIC-031.
- До TASK-031-1 API `/predict/upcoming` имел скользящее окно 48 часов, а бот
  объединял до десяти прогнозов в одно сообщение.
- Control API сейчас поддерживает `SUPPORTED_PIPELINES = {"nhl"}`. Общий
  интерфейс управления не создаёт поддержку нового турнира в серверном цикле.

## Предположения и открытые вопросы

- Интерфейс Telegram-бота для владельца подтверждён; точные шаги диалога и
  формат подтверждения ставки остаются техническим решением.
- Владелец подтвердил раздельный учёт: общий денежный PnL объединяет результат
  собственных ставок и денежные выплаты фрибетов; ROI рассчитывается только
  для ставок собственными деньгами, номинал и выплаты фрибетов видны отдельно.
- Валюта первого среза — RUB; финансовый месяц определяется датой расчёта.
  Открытые ставки доступны отдельным списком без финансовой агрегации.
- Для фрибета подтверждено отсутствие возврата номинала при выигрыше и его
  сгорание при void. Частичный расчёт не входит в первый срез.
- Эффективность промо-номинала как отдельный процент пока не предложена для
  первого среза; номинал и полученные деньги видны отдельно.
- Ставка без prediction revision разрешена; отсутствие ссылки показывается
  явно. Автоматически достраивать её задним числом нельзя.
- Ошибочно введённая запись может быть помечена как отменённая с причиной
  и сохранённой историей; она не учитывается в финансовой сводке. Физическое
  удаление через пользовательский интерфейс не требуется.

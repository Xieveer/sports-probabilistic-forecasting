# REQ-006 — Первое подтверждённое Telegram-сообщение

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-08-09

## Результат и ценность

Владелец продукта получает в своём Telegram одно контролируемое сообщение от
развёрнутого production-кандидата и может соотнести его с конкретной версией
release. Это является первым наблюдаемым доказательством, что сервис создаёт
ценность за пределами локального кода и документации.

## Scope

- Отдельная проверка пользовательской доставки после разрешённого rollout:
  выбранный получатель, распознаваемый безопасный текст, фиксируемый результат
  доставки и корреляция с release image/model version.
- Разделение non-mutating технического acceptance и действия, которое
  действительно отправляет Telegram-сообщение.
- Release/security gate, необходимые для законного запуска production-кандидата,
  и операционный evidence без токенов, chat ID и тел внешних ответов.

## Non-scope

- Автоматический production deployment, публикация образов, управление VPS или
  секретами без отдельного разрешения владельца.
- Массовая рассылка, новые пользовательские прогнозные функции и изменение
  обычного расписания NHL digest.
- Ослабление security gate ради отправки тестового сообщения.

## Сценарии

1. После прохождения release gates и явного разрешения владельца оператор
   развёртывает кандидат, выполняет технический acceptance, затем однократно
   запускает контролируемую проверку доставки выбранному получателю. Владелец
   получает сообщение и подтверждает факт получения.
2. Если delivery, bot, Telegram API либо release gate неуспешны, сообщение не
   считается доставленным; оператор получает безопасный диагностический статус,
   а rollout не объявляется подтверждённым.

## Критерии приёмки

- [ ] Существует отдельный от non-mutating acceptance контролируемый сценарий
  первой доставки, который не может запускаться расписанием или обычным retry.
- [ ] Сценарий использует production-кандидат с зафиксированными image/model
  identity и не раскрывает секреты, chat ID либо Telegram response body.
- [ ] До запуска устранён либо формально принят владельцем security release
  blocker; опубликованы требуемые immutable images и evidence их проверок.
- [ ] Есть evidence технической готовности, успешного запуска delivery-сценария
  и подтверждение владельца о фактическом получении сообщения.
- [ ] Без отдельного разрешения владельца deployment и отправка не выполняются.

## Ограничения, зависимости и риски

- `REQ-005` и `ADR-005` сохраняют границу production serving-контура; текущий
  handoff запрещает rollout при незакрытом security audit.
- Telegram HTTP и запись статуса доставки не образуют строго exactly-once
  транзакцию; повтор должен быть явным операторским действием.
- Реальные токены и идентификатор получателя остаются только в secret store.

## Предположения и открытые вопросы

- Получатель первой проверки будет задан владельцем через защищённый
  operator environment; его идентификатор не попадёт в репозиторий.
- Отдельное разрешение на rollout и внешнюю отправку ещё не дано.

## Подтверждение

Потребность зафиксирована владельцем продукта в диалоге 2026-08-09: сервис
должен дать наблюдаемый бизнес-результат, а не только подготовленный код; владелец
поручил оформить backlog.

# REQ-009 — Проверяемые gates процесса Codex-агентов

> **Статус:** confirmed
> **Владелец продукта:** пользователь проекта
> **Создано:** 2026-08-16

## Результат и ценность

Владелец проекта получает воспроизводимый процесс: бизнес-требования превращаются в
архитектуру, EPIC и небольшие TASK; независимый reviewer является единственной ролью,
которая делает commit/push после review. Это исключает неявную смену ответственности и
закрытие EPIC без сквозной проверки.

## Scope

- Явный контракт этапов и документационных handoff в правилах, roles и skills.
- Исполнимая `make ai-validate` проверка прав reviewer и обязательных process-gates.
- Шаблоны EPIC, TASK и отчёта, в которых есть review и commit evidence.

## Non-scope

- Изменение прикладного кода прогнозирования и production deployment.
- Автоматический фактический push в удалённый Git-репозиторий.

## Сценарии

1. Для новой возможности агент создаёт confirmed REQ, ADR при значимом решении, EPIC и
   независимые TASK с проверками.
2. Implementer завершает TASK и документацию, а reviewer обнаруживает findings либо
   выполняет commit/push только после чистого review.
3. После terminal-статусов всех TASK reviewer проводит полное EPIC review и лишь затем
   фиксирует завершение EPIC.
4. Профиль reviewer случайно переводят в read-only — `make ai-validate` завершается ошибкой.

## Критерии приёмки

- [x] Канонические инструкции описывают все этапы, владельцев и условия перехода.
- [x] Reviewer имеет техническую возможность выполнить назначенный commit/push gate, но не
  исправляет production-код автора во время review.
- [x] `make ai-validate` проверяет reviewer profile и обязательные TASK/EPIC/documentation gates.
- [x] Шаблоны сохраняют evidence review и commit/push для TASK и EPIC.

## Ограничения, зависимости и риски

- Push остаётся внешним действием и требует обычной авторизации Git; проверка не подменяет
  реальное независимое review.

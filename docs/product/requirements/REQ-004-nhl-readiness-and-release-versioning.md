# REQ-004 — Готовность NHL и версия релиза

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-08-08

## Результат и ценность

Перед первым production-развёртыванием сервис подтверждённо обрабатывает NHL в
межсезонье: дозагружает результаты завершившегося сезона, получает доступные
исторические коэффициенты и, при опубликованном расписании нового сезона,
создаёт прогнозы будущих матчей. Поставляемая на production версия сервиса
имеет понятный отраслевой номер `1.0.0`, а ключи The Odds API расходуются в
согласованном порядке: бесплатный, затем подписка на 20 000 запросов и затем
подписка на 100 000 запросов.

## Scope

- Проверка фактической работоспособности NHL-контура на данных межсезонья:
  полнота локально сохранённых завершённых матчей, исторические коэффициенты и
  обработка доступного будущего расписания.
- Дозагрузка отсутствующих завершённых NHL-матчей в пределах доступности
  официального источника без удаления имеющихся данных.
- Запрос и сохранение доступных коэффициентов The Odds API для прошедших
  матчей в пределах доступности API и выделенных квот.
- Выдача прогнозов матчей будущего сезона, только если расписание опубликовано
  источником и прошло существующие проверки качества.
- Введение единого Semantic Versioning для поставляемого сервиса, Git-тега и
  Docker-образа; первый production-релиз имеет версию `1.0.0`.
- Добавление в `.env.example` трёх пустых переменных для ключей The Odds API и
  выбор ключа в порядке: бесплатный → 20 000 → 100 000.
- Безопасный переход к следующему ключу только при доказанном исчерпании или
  недоступности квоты предыдущего ключа; секреты не попадают в логи, код и
  артефакты данных.

## Non-scope

- Production-развёртывание, публикация релиза, создание или ротация реальных
  ключей The Odds API.
- Гарантия появления расписания NHL или исторических коэффициентов, если
  внешний поставщик их ещё не публикует либо не предоставляет тарифу.
- Покупка либо изменение тарифов The Odds API.
- Изменение рынков, моделей и методики прогнозирования, не требуемое для
  проверки NHL-контура.

## Сценарии

1. Оператор запускает NHL refresh в межсезонье. Сервис дозагружает доступные
   завершённые матчи, подтверждает полноту результатов и фиксирует понятный
   результат проверки.
2. Для завершённых матчей запрашиваются исторические коэффициенты. Пока у
   бесплатного ключа есть квота и запросы успешны, используется только он;
   при исчерпании/недоступности — ключ 20 000, затем 100 000. Если подходящего
   ключа нет либо все квоты недоступны, сервис завершает операцию безопасно и
   сообщает причину без раскрытия ключа.
3. Источник опубликовал будущие матчи NHL. После прохождения quality gate для
   таких матчей сервис материализует прогнозы; при отсутствии расписания это
   считается штатным результатом, а не ошибкой.
4. Оператор видит версию поставляемого сервиса как `1.0.0`, а будущий выпуск
   помечается Git-тегом и Docker-образом `1.0.0`.

## Критерии приёмки

- [ ] Проверка NHL-контуров выполнена на фактических данных межсезонья; отчёт
  отделяет полученные данные от объективно недоступных у внешних источников.
- [ ] Все доступные после последнего локально сохранённого результата
  завершённые NHL-матчи сохранены без пропусков, дублей и повреждения
  обязательных полей либо проверка завершилась наблюдаемой ошибкой источника.
- [ ] Для доступных исторических матчей коэффициенты The Odds API запрошены и
  обработаны по существующему контракту, без записи ключей в логи или репозиторий.
- [ ] `.env.example` содержит отдельные пустые переменные для бесплатного ключа,
  ключа тарифа 20 000 и ключа тарифа 100 000 с русскими пояснениями порядка
  приоритета.
- [ ] При наличии всех трёх ключей первый успешный запрос использует бесплатный
  ключ; следующий ключ применяется лишь после подтверждённого отказа или
  исчерпания квоты предыдущего.
- [ ] При отсутствии будущего расписания NHL сервис не формирует фиктивные
  прогнозы и завершает соответствующий этап без ложной ошибки.
- [ ] При наличии и успешной валидации будущего расписания NHL сервис может
  материализовать прогнозы для опубликованных матчей.
- [ ] Поставляемая версия сервиса следует SemVer и для первого production-релиза
  равна `1.0.0`; будущие Git-тег и Docker-образ используют то же значение, а
  прежние несогласованные значения не вводят оператора в заблуждение.

## Ограничения, зависимости и риски

- Доступность будущего расписания и исторических коэффициентов определяется
  NHL API и The Odds API, а не сервисом.
- Переключение ключей требует надёжно отличать исчерпанную/недоступную квоту от
  ошибок сети, схемы и авторизации, чтобы не расходовать платные квоты ошибочно.
- Версия релиза, версия API и версии моделей могут иметь разные назначения;
  их точки публикации должны быть явно определены до реализации.

## Предположения и открытые вопросы

- Предполагается, что три ключа принадлежат независимым квотам и допустимо
  использовать их в заданном порядке согласно условиям The Odds API.
- Имена переменных окружения и точный сигнал исчерпания квоты будут определены
  после изучения подтверждённого контракта The Odds API и текущего клиента.

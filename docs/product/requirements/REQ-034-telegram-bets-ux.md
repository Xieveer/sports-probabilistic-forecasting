# REQ-034 — Универсальная запись и история ставок

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-10-11
> **Инициатива:** [EPIC-034](../../backlog/EPIC-034-telegram-bets-ux.md)

## Результат и ценность

После записи ставки чат Telegram не заполняется сообщениями пошагового диалога.
Владелец может записать ставку на матч нужного турнира без привязки команды
`/bet_add` к NHL и анализировать фактические ставки по турнирам. Он получает
шаблон Excel для ранее сделанных ставок и перенос истории в серверный журнал
фактических ставок после проверки источников и финансовых значений.

## Подтверждённый запрос владельца

1. После нажатия «Записать ставку», прохождения вопросов и успешного сохранения
   удалить сообщения, относящиеся к записи этой ставки, чтобы не оставлять шум
   в чате.
2. Подготовить шаблон Excel для уже существующей истории ставок. Владелец
   заполнит его; после передачи заполненного файла требуется записать данные
   в серверную БД.
3. Убрать жёсткую привязку `/bet_add` к NHL: регистрация фактических ставок
   должна быть универсальной по турнирам. Для каждой ставки указывать турнир,
   к которому она относится, чтобы затем анализировать ставки в разных срезах.
4. В подсказке `/bet_correct` показывать понятный шаблон команды и конкретные
   примеры допустимых значений, чтобы владелец не ошибался при исправлении
   ставки.
5. 2026-10-11 владелец разрешил начать реализацию. Запись исторических ставок
   на сервер возможна после получения заполненного файла.

## Сценарии и критерии приёмки

- [x] После успешного сохранения записи сообщения пошагового диалога, включая
  ввод владельца и финальное «Ставка сохранена», удалены из личного чата.
  Исходная карточка прогноза остаётся для следующей отдельной ставки.
- [x] При ошибке сохранения владелец может повторить подтверждение, а введённые
  данные и возможность понять причину ошибки сохраняются до успешной записи.
- [x] Шаблон позволяет указать каждую ранее размещённую одиночную ставку
  отдельной строкой, включая повторные ставки на один матч. Турнир каждой
  ставки указывается явно. Первый файл охватывает только Winline, RUB,
  собственные средства и фрибеты, открытые и рассчитанные ставки.
- [x] По переданным скриншотам подготовлен заполненный файл, история перенесена
  без дубликатов после проверки данных. Количество 59 записей, 59 audit и
  денежные итоги сверены с файлом и сервером; повторный запуск не добавил
  записей. Подробности — в [отчёте TASK-034-4](../../changes/done/TASK-034-4-historical-bets-import.md).
- [x] Владелец начинает запись через `/bet_add` для матча доступного турнира;
  сохранённая ставка содержит соответствующий турнир. Команда не подставляет
  NHL без выбора или указания владельца.
- [x] Владелец получает срез фактических ставок и денежных итогов по турнирам;
  итог по всем турнирам сходится с суммой турнирных срезов по действующим
  финансовым правилам. Первый срез добавлен в месячный `/bet_report`.
- [x] При вызове `/bet_correct` без аргументов или с неполными аргументами бот
  показывает шаблон `/bet_correct ID_ставки поле значение` и готовые примеры
  для суммы, коэффициента, типа средств, исхода, результата, даты/времени,
  отмены с причиной и повторного открытия без значения. ID предлагается
  скопировать из истории ставок; подсказка объясняет формат времени МСК и
  перечисляет допустимые значения `cash`/`freebet` и `win`/`loss`/`void`.
  Примеры для `outcome` должны соответствовать рынку конкретной ставки.
- [x] Ошибка в значении `/bet_correct` объясняет ожидаемый формат для выбранного
  поля и показывает корректный пример. Подсказка не предлагает синтаксис,
  который текущая команда не сможет обработать.

## Предлагаемый вид примеров `/bet_correct`

Здесь `ID_ставки` — обозначение UUID из `/bet_history`, а не буквальный текст
для ввода. Реализованная подсказка показывает копируемые примеры.

```text
/bet_correct ID_ставки stake 500,50
/bet_correct ID_ставки odds 2,35
/bet_correct ID_ставки payout 1176,18
/bet_correct ID_ставки funding freebet
/bet_correct ID_ставки outcome home_win
/bet_correct ID_ставки result win
/bet_correct ID_ставки placed_at 11.10.2026 19:30
/bet_correct ID_ставки settled_at 12.10.2026 00:15
/bet_correct ID_ставки cancel Ошибочно записана дважды
/bet_correct ID_ставки reopen
```

Пример `outcome home_win` относится только к рынку `winner_withOT`; для
другого рынка подсказка должна показывать его допустимые исходы. Исправление
`result` открытой ставки зависит также от заполненных выплаты и времени
расчёта: подсказка должна объяснять это условие, чтобы отдельный пример
`result win` не обещал успешное изменение любой открытой записи.

## Текущие ограничения и зависимости

- Действующий журнал описан в [REQ-031](REQ-031-real-bets-ledger.md): одно
  фактическое размещение — отдельная запись; учитываются исход, рынок,
  bookmaker, тип средств, номинал, фактический коэффициент, время размещения,
  а для рассчитанной ставки — результат, фактическая выплата и время расчёта.
  Денежные правила для обычных ставок и фрибетов сохраняются.
- Записи журнала связаны с событием и, если доступно, с версией прогноза.
  Для старых ставок наличие исходной версии прогноза и котировки нельзя
  предполагать; фиктивные связи создавать нельзя.
- До EPIC-034 `/bet_add` передавал `tournament=nhl`, а API ручного контекста
  отклонял другие турниры. Изменения первого среза находятся в `main`;
  production `v1.3.1` продолжает работать на прежнем коде до отдельного
  запроса на deployment.
- Текущий `/bet_correct` принимает команду с ID, именем поля и значением;
  для `reopen` значение отсутствует, а для `cancel` нужна непустая причина.
  Суммы принимают рубли с точностью до копейки, коэффициент — decimal больше
  единицы до четырёх знаков после запятой, время — `ДД.ММ.ГГГГ ЧЧ:ММ` МСК.
- История перенесена в действующую production БД по исходному запросу владельца
  после проверки скриншотов, файла и server readback. Истинное время размещения
  и расчёта не восстановлено: применены согласованные условные значения.

## Открытые вопросы

- Включать ли в очистку сценарий `/bet_add` из календаря, ошибочные ответы,
  отменённый диалог и диалог расчёта уже сохранённой ставки?
- Как идентифицировать старые матчи, отсутствующие в каталоге событий, если
  появится новая партия истории? Все матчи текущей партии сопоставлены.
- Какие дополнительные рынки нужны для ручной записи? Для них требуются
  явные правила исходов и расчёта, без переноса NHL-правила `winner_withOT`.
- Дополнительный фильтр списка ставок по турниру и сочетание срезов можно
  уточнить по результату использования месячного `/bet_report`.
- Для будущих партий истории без скриншотов расчёта или выплат потребуется
  отдельное правило; текущая партия содержит фактические выплаты и условные
  времена.

## Подтверждение

Пункты об очистке, истории, универсальном `/bet_add` и подсказке `/bet_correct`
получены 2026-10-11. Владелец разрешил начать работу 2026-10-11 и уточнил:
удалять также финальное подтверждение, оставлять карточку прогноза; первый
шаблон — одиночные Winline в RUB, в том числе фрибеты и рассчитанные ставки.
В тот же день владелец передал 30 скриншотов вместо ручного заполнения и
поручил перенести их в таблицу. Условные времена: ставка в 11:00 МСК,
расчёт через три часа после начала матча; для одного купона владелец
отдельно согласовал предыдущий день в 11:00, чтобы ставка предшествовала
началу события.

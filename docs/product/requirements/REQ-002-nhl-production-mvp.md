# REQ-002 — NHL production MVP

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-08-07

## Результат и ценность

Пользователи Telegram из разрешённого списка ежедневно получают вероятностный
прогноз NHL на ближайшие 48 часов и последующее обновление коэффициентов. Это
позволяет пользоваться актуальным прогнозом независимо от того, появились ли
коэффициенты к моменту первого обновления.

Внешним пользовательским каналом MVP является только Telegram-бот. API остаётся
техническим read-only интерфейсом для бота и не публикуется и не документируется
как канал для конечных пользователей.

## Scope

- Ежедневное обновление NHL-данных и материализация прогнозов с первым запуском
  в 10:00 по московскому времени.
- Автоматическая отправка всем пользователям из allowlist прогноза матчей на
  ближайшие 48 часов после успешного обновления данных.
- Отправка прогноза без ожидания коэффициентов.
- Опрос источника коэффициентов не реже одного раза в 15 минут, пока они нужны
  для релевантных матчей, и автоматическая рассылка обновления при появлении
  либо изменении коэффициентов.
- Выдача по запросу актуального прогноза и доступного состояния коэффициентов.
- Уведомление администратора через Telegram о неуспешном завершении сценария.

## Non-scope

- Публичный пользовательский доступ к API.
- Уведомление пользователей об окончательном отсутствии коэффициентов.
- Подробная трассировка ошибок и настройка Grafana на production-сервере.
- Выполнение production-развёртывания без отдельной авторизации владельца.

## Сценарии

1. В 10:00 МСК выполняется обновление NHL. Данные проходят проверки, прогнозы
   материализуются, и каждый пользователь из allowlist получает прогноз на
   ближайшие 48 часов, даже если коэффициентов ещё нет.
2. Для релевантного матча коэффициенты отсутствуют после первого обновления.
   Сервис проверяет их появление как минимум раз в 15 минут и рассылает
   обновление всем пользователям из allowlist, когда они становятся доступны.
   Один цикл опроса формирует одно итоговое сообщение со всеми найденными
   изменениями: как с новыми коэффициентами, так и с обновлением уже известных.
3. Пользователь из allowlist запрашивает данные и получает текущий прогноз на
   ближайшие 48 часов вместе с доступным состоянием коэффициентов.
4. Обновление данных завершается ошибкой либо проверка качества не пройдена.
   Прогноз и сообщение об успешном обновлении не отправляются; администратор
   получает краткое уведомление о неуспешном сценарии.
5. Коэффициенты не появились до начала матча. Пользователи не получают
   отдельного сообщения об их отсутствии.
6. Источник вернул расписание либо результаты, которых нет в локальных NHL-данных.
   Сценарий сохраняет каждую отсутствующую запись; перед рассылкой проверяется,
   что расписание матчей на ближайшие 48 часов и результаты, начиная с последнего
   локально сохранённого завершённого матча, получены без пропусков и битых
   обязательных полей.

## Критерии приёмки

- [ ] NHL-обновление стартует ежедневно в 10:00 МСК; параллельный запуск не
  создаёт дублирующую обработку.
- [ ] Если обновление, проверка качества и материализация успешны, каждый
  пользователь из allowlist получает ровно один прогнозный дайджест матчей на
  ближайшие 48 часов.
- [ ] Прогнозный дайджест отправляется при отсутствии коэффициентов.
- [ ] Пока коэффициенты релевантных матчей отсутствуют, их источник
  опрашивается не реже одного раза в 15 минут; при появлении либо изменении
  коэффициентов каждый пользователь из allowlist получает одно агрегированное
  обновление за цикл опроса.
- [ ] Если в цикле опроса не найдено новых или изменённых коэффициентов,
  пользователям не отправляется сообщение.
- [ ] Опрос прекращается, когда коэффициенты получены либо матч начался.
- [ ] Пользователь из allowlist по запросу получает актуальные прогнозы и
  доступные коэффициенты, а пользователь вне allowlist не получает прогнозные
  или служебные данные.
- [ ] Конечный пользователь получает прогнозные и служебные данные только через
  Telegram-бот; API не публикуется и не документируется как пользовательский
  канал.
- [ ] Перед рассылкой отдельный NHL quality gate подтверждает, что все матчи,
  возвращённые источником на ближайшие 48 часов, сохранены без пропусков и
  дублей, а у каждого завершённого матча от даты последнего локально
  сохранённого завершённого матча до даты refresh сохранены итоговый результат и
  обязательные поля не повреждены.
- [ ] При ошибке сценария или непрохождении проверки качества не рассылаются
  прогноз и сообщение об успехе; краткое уведомление получает только
  администратор.

## Ограничения, зависимости и риски

- Доставка коэффициентов зависит от внешнего источника; время их появления не
  гарантировано.
- Текущие schema/duplicate quality gates не проверяют полноту будущего расписания
  и дозагрузку отсутствующих результатов; для MVP требуется отдельная NHL-проверка.
- При ежедневном нормальном выполнении проверка результатов обычно покрывает
  матчи предыдущего дня; повторная проверка небольшого перекрывающегося интервала
  допустима для исправлений источника.
- Доступ пользователей определяется allowlist, а получатель уведомлений об
  ошибках — отдельным списком администраторов Telegram.
- Бизнесовый scope MVP ограничен NHL, но код оркестрации, quality gate и
  уведомлений не содержит ветвей с NHL-значениями. Турнир, источник, рынки,
  окно прогноза, расписания, поля результата и политика коэффициентов задаются
  отдельным конфигурационным профилем.

## Предположения и открытые вопросы

- Предполагается, что после начала матча коэффициенты для него больше не нужны
  для данного пользовательского сценария.
- Под «последним матчем в данных» понимается последний локально сохранённый
  завершённый матч с итоговым результатом, а не последняя будущая запись
  расписания.
- Конкретные механизмы планирования, изоляции внутреннего API, хранения
  состояния и защиты секретов не выбраны: они относятся к архитектурному
  планированию.

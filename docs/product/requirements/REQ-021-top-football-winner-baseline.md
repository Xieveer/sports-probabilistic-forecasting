# REQ-021 — Базовый winner-прогноз для топовых футбольных лиг

> **Статус:** confirmed
> **Владелец продукта:** пользователь
> **Создано:** 2026-09-08

## Результат и ценность

Провести полный воспроизводимый Research Mode цикл для предматчевого рынка `winner` (1X2)
по согласованному набору топовых клубных футбольных лиг. Успех исследования требует на
locked holdout прошлого сезона ROI не ниже 5% и coverage выбранных ставок выше 20%, без
утверждения о production edge.

## Scope

- По подтверждённому каталогу Smart Tables определить и зафиксировать поля, допустимые
  для подготовки предматчевых фичей, и отдельно пометить post-event поля.
- Включить Big Five Европы, РПЛ, ФНЛ, Лигу чемпионов и Лигу Европы.
- Настроить отдельный ingest-slug для согласованного пула клубных лиг, bronze/raw слой,
  очистку в interim и quality gates.
- Построить processed features через существующие генераторы; не использовать значения,
  которых не было до kickoff.
- Сформулировать фальсифицируемые гипотезы для будущих фичей с потребностями в данных и
  рисками leakage.
- Обучить и сохранить CatBoost baseline для `winner` с temporal validation и метриками
  вероятностного качества.
- Включить historical 1X2 `odd_home`/`odd_x`/`odd_away` из Smart Tables в отдельный
  backtest-слой, измерить его coverage и применимость для ROI.
- Расширить Research Goal/Evaluation Harness критерием `min_coverage`, чтобы ROI и coverage
  были детерминированными gate, а не ручным выводом.

## Non-scope

- Betting-стратегия, ROI/EV/CLV, promotion, materialization, Airflow и production deployment.
- Использование post-event score/stat/chart как предматчевых фичей.
- Обход CAPTCHA, ACL, rate-limit либо неподтверждённой лицензии Smart Tables.

## Сценарии

1. Оператор запускает ingest согласованных лиг; сырые нормализованные данные и provenance
   сохраняются отдельно от существующего пула сборных, затем clean создаёт валидный interim.
2. Оператор строит `features=advanced`; processed dataset содержит лишь lagged/rolling
   признаки, доступные до матча.
3. Оператор запускает CatBoost для `winner`; результат фиксирует temporal split, LogLoss,
   Brier score, калибровку, ROI и coverage без утверждений о betting edge.
4. API возвращает пропущенную статистику, дубликат или незавершённый матч; quality gate
   фиксирует/исключает запись по документированному правилу без подмены результата.

## Критерии приёмки

- [ ] Набор лиг, их Smart Tables `competition_id`/`code`/slug и граница периода явно
  зафиксированы в конфигурации и документации.
- [ ] Для каждого используемого поля известны источник, temporal-класс и правило
  очистки; post-event поля не попадают в модель как текущий матч.
- [ ] Ingest создаёт отдельные source/raw/interim артефакты и воспроизводимо проходит
  schema/quality validation на fixture или контролируемом малом наборе.
- [ ] Existing generators создают processed features без target leakage; это покрыто
  регрессионным тестом.
- [ ] CatBoost `winner` обучается на временном train/validation/test разделении и
  записывает метрики вероятностного качества и состав признаков.
- [ ] На locked holdout прошлого сезона backtest использует только ставки с историческим
  1X2-коэффициентом, показывает ROI не ниже 5% и coverage выше 20%; при невыполнении хотя
  бы одного условия Harness возвращает `FAIL`.
- [ ] Документ содержит не менее трёх новых фальсифицируемых feature hypotheses с
  required data, expected information gain и leakage risks.

## Ограничения, зависимости и риски

- Каталог Smart Tables подтверждает клубные записи: ENG1 (id 13), SPA1 (id 5), GER1
  (id 3), ITA1 (id 2), FRA1 (id 1), RUS1 (id 14), RUS2 (id 66), UCL (id 16), UEL
  (id 18). Полный клубный coverage и автоматизированная production-лицензия не доказаны.
- Read-only проверка API 2026-09-12 подтвердила у исторических finished матчей всех четырёх
  добавленных турниров ненулевые `odd_home`, `odd_x`, `odd_away`: РПЛ с 2015-07-17, ФНЛ с
  2017-07-08, ЛЧ с 2015-09-15, ЛЕ с 2015-09-17. Это подтверждает наличие 1X2-значений,
  но не timestamp снимка, букмекера, тип линии (opening/closing) или полноту покрытия.
- `score`, finished match stats и chart являются post-event. `odd_*` могут применяться для
  backtest только после решения об их temporal policy.
- Потребуется явное ограничение запросов и возможность продолжить backfill из cache.
- Результат модели и даже положительный holdout ROI не являются доказательством устойчивого
  production edge без source provenance, robustness checks и нового out-of-sample периода.

## Предположения и открытые вопросы

- **Подтверждено пользователем:** пул содержит Big Five Европы (Premier League, La Liga,
  Bundesliga, Serie A, Ligue 1), РПЛ, ФНЛ, Лигу чемпионов и Лигу Европы.
- **Предположение:** прошлый сезон для locked holdout — 2025/26; development и validation
  используют только матчи, завершившиеся до его начала.
- **Подтверждено пользователем:** для этого исследования единственная историческая тройка
  `odd_home`/`odd_x`/`odd_away` принимается как последняя доступная prematch-котировка.
  Неопределённость timestamp, букмекера и closing-статуса остаётся обязательным caveat.
- **Предположение:** базовый рынок `winner` — трёхклассовый 1X2, а не бинарный `home_win`.
  Это требует проверки текущего market-spec/target contract перед реализацией.

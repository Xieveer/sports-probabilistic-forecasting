# Checklist безопасности

Применять только к затронутым границам, а не механически ко всему списку.

## Входы и данные

- Недоверенный ввод валидируется по типу, размеру и допустимому содержимому.
- Пути нормализуются и остаются внутри разрешённой директории.
- Парсеры имеют лимиты и безопасное поведение при ошибке.
- Персональные данные минимизированы и имеют понятный срок хранения.

## Доступ

- Authentication подтверждает субъект.
- Authorization проверяется на серверной границе для каждого ресурса.
- Идентификатор от клиента не является доказательством владения.
- Ошибки не раскрывают существование чужого ресурса.

## Секреты и логи

- Секреты поступают извне и отсутствуют в Git, image layers и tests.
- Логи не содержат token, cookie, полный message или API response.
- Отчёт безопасности маскирует найденное значение.

## Сеть и зависимости

- Есть timeout, ограниченный retry и rate limit.
- TLS verification не отключена.
- Новая зависимость обоснована, закреплена и проверена audit-инструментом.
- GitHub Actions и container images закреплены воспроизводимой версией/SHA.

## CI и Docker

- `GITHUB_TOKEN` имеет минимальные permissions.
- Secrets недоступны недоверенному fork-коду.
- Runtime работает не от root.
- Security gate не использует `continue-on-error`.
